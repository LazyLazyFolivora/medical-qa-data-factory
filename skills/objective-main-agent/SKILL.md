# 主 Agent 出题调度

> 旧协议参考。当前 Web/CLI 外层已切换到 [objective-react-agent](../objective-react-agent/SKILL.md)，本文件的固定阶段描述不控制新任务。

本文件是项目 skill 草案，尚未接入 `StructuredMainAgent.decide()`。每次决策从宿主提供的合法动作中选择一个，由程序执行、记录状态和发布。当前运行时的限制及修复缺口见 [references/current-runtime.md](references/current-runtime.md)，接入或执行当前协议前需阅读。

跨阶段输入、隔离与结果含义见 [references/stage-handoffs.md](references/stage-handoffs.md)，配置整条流程时读取。该说明用于对齐职责，不是已经实现的新数据接口。

## 共同目标

生成适合 query-planner 检索与证据整合、客观正确且题干自包含的问题。数量目标、难度目标和成本约束不能成为放宽事实要求的理由。

主 Agent 管理缺口、探索方向和阶段推进，不直接提取已验证事实、不代替答案验证、不编写或发布标准答案。材料摘要用于选择动作，不是完整医学证据。

## 每轮观察

检查目标实体、事实类型、目标难度、数量、可用 provider、剩余预算、当前合法动作，以及材料、事实、假设、契约、草稿和审核结果的状态。

区分：已完成的检查、有材料但尚未检查的事项、实际失败的检查、输入缺失导致未知的事项。不能把 artifact 存在、来源数量增加或工具成功当作问题质量已通过。

摘要没有具体失败原因时，不自行推测。利用当前允许的诊断获取方式核对；若协议没有提供该能力，记录输入缺口，不通过重复调用原动作来假装修复。

## 动作选择

| 当前情况 | 候选动作 | 决策依据 |
|---|---|---|
| 只有实体，缺少具体材料 | `retrieve_materials` | 先消歧，再选适合实体类型的少量方向及来源 |
| 已有未理解的相关材料和锚点 | `understand_facts` | 让事实理解保留条件、关系和出处，避免无限积累材料 |
| 有可用事实，设计阶段合法 | `design_questions` | 事实能支持目标难度的任务；允许设计者报告材料不足 |
| 缺少关键条件、关系、独立支持或竞争答案依据 | `request_more_evidence` 或 `retrieve_materials` | 明确缺口，选择合适用途、provider 和查询 |
| 有活跃候选及相关验证材料 | `verify_answer` | 材料与该候选范围有关；不因任意 verification 结果存在就默认足够 |
| 有已验证且未写作的冻结契约 | `realize_question` | 写作只表达已验证语义，不能再新增事实 |
| 有未审核草稿和已验证契约 | `review_release` | 对实际题目检查客观性、自包含、Planner 适配及要求的难度 |
| 已达发布目标且宿主允许 | `stop` | 不再为完成数量追加无必要动作 |

表格表达语义上的选择依据，不扩大合法动作空间。缺少前置产物时先补前置步骤，不跳过验证或审核。

多个动作都合法时，优先选择能解决当前具体阻塞、推进已有有效候选的动作。对低价值或反复失败的方向考虑切换，不因已有投入而无限追加检索；切换也须保留已有结果和失败原因。

## 规划检索任务

初始只有实体时，根据实体类型及事实类型选一到两个合理方向。给定目标难度时，简单题可查直接属性，中等题可查相连关系，困难题可查有区分作用的条件和比较对象；不能预设关系必然存在。

后续检索必须回答“补什么、为什么补、什么结果能改变下一步”。把已知实体、实际条件和缺口表达进 provider 支持的查询，并通过支持的交接字段传给子 Agent。

`discovery` 用于发现或丰富候选事实；`verification` 用于针对候选语义的独立核验。独立性取决于来源上游，而不只是 provider 名不同。查询失败、空结果、低相关性和重复材料应分别处理。

同一子任务内由检索 Agent 改写查询；跨来源和跨方向由主 Agent 决定。只使用配置的 provider 及字段，不凭空扩展工具权限。

## 按缺陷安排下一步

| 发现的问题 | 应回到的职责 | 不应采取的做法 |
|---|---|---|
| 实体不清、材料缺条件、关键关系没有依据 | 检索与事实理解 | 编造限定条件或连接关系 |
| 设计范围过宽、单答案实际多解、题目不适合 Planner | 问题设计 | 反复写同一题面或只搜索原候选答案 |
| 答案可能正确但独立支持、闭合依据或反证检查不足 | 补查与答案验证 | 把不确定写成通过或把检索失败写成否定事实 |
| 事实成立，但题面漏条件、提示答案或措辞不准确 | 保留有效契约的题面重写，再审核 | 隐藏失败记录或直接发布修改稿 |
| 难度与实际检索任务不符 | 问题设计；降级须符合任务授权 | 强制工具绕路、删除条件或增加无关背景 |
| Planner 环境未知或已知不支持所需证据 | 环境确认或任务选择 | 改用“当前数据库中”来缩小事实含义 |
| 模型格式、provider 或预算错误 | 相应执行恢复与运行诊断 | 把工程失败伪装成医学结论 |

上述是职责路由，不代表当前接口支持对同一候选的重写或重新验证。只在宿主显式支持相应动作和版本状态时执行。否则记录恢复缺口，使用合法的替代设计路径；不得编造 `rewrite`、`reopen` 或直接修改状态。

## 进展、预算与停止

有意义的进展包括新增相关事实、补齐公开条件、排除真实歧义、确认独立支持、完成某项验证或修复已知题面缺陷。重复材料、重复答案和相同失败不算进展。

在调用前检查提供的预算和次数限制，避免发起已知无法完成的同类重试。成本或次数超限交由宿主处理，不能用错误事实凑足目标。

区分停止某个检索方向和结束整个运行。已达目标且 STOP 合法时停止；未达目标但无有效路径时，应由宿主的失败或阻塞机制结束并保留诊断。当前没有这类动作时不伪造成功 STOP、不用无意义调用刻意耗尽预算；这是需要接入的运行能力缺口。

## 输出与阶段规范

遵守宿主决策 schema，选择一个合法 action，使用实际存在的输入产物和正确 role。动作参数按协议给出，信息增益只能作为动作价值估计，不作为医学置信度。身份、digest 和发布由宿主管理。

分派阶段时应让相应执行者获得自己的 skill 及必要输入，不把所有全文无差别塞进每个调用：

- 检索：[objective-material-retrieval](../objective-material-retrieval/SKILL.md)。
- 事实理解：[objective-fact-understanding](../objective-fact-understanding/SKILL.md)。
- 问题设计：[objective-question-design](../objective-question-design/SKILL.md)，按目标难度加载参考。
- 答案验证：[objective-answer-verification](../objective-answer-verification/SKILL.md)。
- 题面写作：[objective-question-realization](../objective-question-realization/SKILL.md)。
- 发布审核：[objective-question-validator](../objective-question-validator/SKILL.md)。

这些链接用于职责和接入定位，不表示当前主循环已自动装载各 skill。调用方需显式实现加载与输入交接。


## 候选题可用性判断（设计后自动执行）

宿主在候选设计后调用 objective-candidate-review，不需要额外规划 action。阅读 candidate_usability_review：
- REJECT 已终止候选：不要围绕其问题缺陷继续补资料，不通过换措辞反复提出同一问题。
- KEEP 可以进入独立答案验证，不表示答案已正确。
- NEEDS_EVIDENCE 仅按 evidence_need 补齐具体缺口；检索无进展时换方向，不因题数或中等难度目标反复补查。
- REWRITE 由宿主最多执行一次改写并复审；不自行编造重写动作。

所有候选淘汰时，优先选择其他有信息价值的事实重新设计，不为恢复已淘汰问题无限检索。判断理由不是证据。
