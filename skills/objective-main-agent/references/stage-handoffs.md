# 七阶段交接与一致性复核

本说明对齐现有 skill 草案，区分设计要求与运行时实现。共同目标始终是适合 query-planner 的检索任务、客观正确、题干自包含；不扩展到训练元数据导出。

## 输入、交付与不能越权的结论

| 阶段 | 应收到什么 | 应交付什么 | 当前成功不代表什么 |
|---|---|---|---|
| 主 Agent | 目标、预算、合法动作、各阶段产物及具体诊断 | 一个合法动作及明确任务需求 | 不能代替验证或批准发布 |
| 检索 | 实体、方向或证据缺口、来源及限制 | 实际材料、锚点、来源、查询记录、未解决项 | 找到材料不证明事实正确或证据完整 |
| 事实理解 | 实体信息、原文、锚点及其对应内容 | 保留条件和强度的候选事实、冲突和缺口 | 可提取不等于已独立验证 |
| 问题设计 | 候选事实、条件、目标难度与查询要求 | 意图、公开范围、候选答案、数量语义、设计依据 | 好设计不等于候选答案成立 |
| 答案验证 | 先隔离盲解输入，再提供候选和独立证据 | 答案状态、核验依据、必要公开条件及可冻结语义 | VERIFIED 不等于最终题面和环境审核已通过 |
| 题面写作 | 冻结契约及明确传递的语言、题型、难度要求 | 实际题面、冻结答案、受支持解释、回读 | 回读一致不证明文本语义一致 |
| 发布审核 | 先仅题面，再提供契约、答案、证据、环境及已要求的难度 | 对原题的阶段判定、具体缺陷和回退建议 | 公开阶段 PASS 不等于整体允许发布 |

## 必须持续传递的信息

- 实体身份、物种等条件、关系方向和强度沿材料、事实、设计、验证、写作、审核保留。必要条件最终必须进入题干，不能只存在于隐藏契约。
- 语言、题型和任务要求的难度从目标进入设计，再明确交给写作与审核。模型自行建议的难度属于暂定标签，不能冒充用户硬要求。
- 来源和查询轨迹进入隐藏验证包，供独立性和覆盖核对，不放进公开题干定义事实。
- 候选答案与发现论证不能进入答案验证的首次盲解；最终答案与证据不能进入发布审核的首次公开题面审查。
- Planner 环境由宿主提供或经实际检查确认，不由各阶段推测。出题资料可访问与 Planner 求解可访问是两件事。
- 修复建议保留具体问题和版本对应关系；不能让后续模型审核原题却使用新版本的契约或答案。

## 统一结果语义

执行成功、材料足够、候选语义 VERIFIED、公开审查 PASS、最终发布 PASS 是不同结论，不能逐层自动继承为质量通过。

有明确缺陷则退回负责该缺陷的阶段；证据不足则补查或暂缓；格式、网络及预算问题保留为执行问题。不用空检索证明不存在，不用几个支持结果证明唯一或全集完整。

审核和验证需要竞争答案、反证材料，但没有工具权限时必须通过主 Agent 请求检索，不能假称已完成搜索。

只修改措辞且语义不变，可保留有效契约并重新审核；改变范围、条件、答案或关系强度，需要重新验证。现有状态机尚未完整实现这些恢复路径。

## 当前接入优先项

1. 按角色加载 skill 和必要参考，保持盲解及公开审核的输入隔离。
2. 传递检索具体需求、真实锚点映射、设计规格和阶段诊断，而不只传用途标签或空摘要。
3. 允许无合格材料、无可用事实、无法设计、契约不足等正常负结果，避免强制填充候选或草稿。
4. 验证阶段获得完整问题上下文并记录真实支持、来源独立性、竞争答案和闭合依据。
5. 显式提供 Planner 环境与要求的难度；对缺失环境导致的审核阻塞不要重复同输入调用。
6. 增加受控重写、重新验证和未达数量目标时的失败退出，协调现有 STOP 限制。

这些是已识别的工程缺口，本次文档复核没有实施代码变更。

## 后续行为试验

用固定材料检查：直接属性题能正常推进；条件缺失回到补查；材料不支持目标难度时不硬凑；一个正确例子不因其他正确例子存在而被拒；完整集合证据不足不会通过；来源转载不算独立；题面漏条件需要重写；改变条件须重验；公开审核不会因看不到隐藏答案而误拒；环境未知不会被假称为可求解。

本轮仅完成静态文本一致性、格式与引用检查。没有运行模型生成或 Planner rollout，不能据此声称生成稳定性已验证。
