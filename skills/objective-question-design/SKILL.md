# 客观问题设计

本规范由运行时按 objective_question_design 角色自动加载，同时加载事实选择方法与目标难度参考。输入是候选事实与原文；输出是自然问句形式的候选题和设计说明。

先按 [references/fact-selection.md](references/fact-selection.md) 读清完整观察、判断第二项事实的信息增量，再设计问题。question_intent 是页面展示的候选问句，不是交给检索器的任务指令。简单题不靠追加名称含义、分类原因或机制说明来增加表面复杂度。

## 输入与适用范围

所有设计同时满足两条最高要求：适合 query-planner 通过检索与证据整合求解；客观正确且题干自包含。题干定义完整的问题，Planner 检索回答问题所需的证据。自包含不意味着题干必须提供答案或解题证据。

使用任务提供的候选事实、证据摘录、限定条件、目标难度及已有题目设计问题。候选答案仍需后续独立验证；设计合理不代表事实已验证或允许发布。

沿用任务指定的语言和题型，缺省优先使用自然的知识查询问法。受众用于校准术语表达；难度主要围绕 Planner 所需的检索、关系连接、条件筛选和证据整合设计。工具与知识源范围未知时明确记录待确认项，不假定出题材料已对 Planner 开放。

任务未指定难度时，可以选择材料能支持的难度并明确说明，不自行决定整个数据集的难度比例。

## 难度路由

为每个候选填写 proposed_difficulty，按最短合理求解路径估计，用于候选排队。仅要求中等时，question_count_upper_bound 约束中等题，附加的简单题不占用该额度。

仅指定中等难度时，优先设计真正需要条件筛选或关系整合的中等题。材料同时支持自然、独立的简单题时可以交付，作为附加产出。不要凑从句把简单题包装成中等题，也不要为了上报简单题挤掉已可设计的中等题。最终难度由答案审核判定。

设计之前读取目标难度的方法和示例：

- 简单：读取 [references/easy.md](references/easy.md)。直接识别一个明确事实。
- 中等：读取 [references/medium.md](references/medium.md)。结合相关事实或限定条件作出判断。
- 困难：读取 [references/hard.md](references/hard.md)。通过必要的多步关系、条件交叉或候选比较确定答案。

难度根据当前工具环境中的必要检索与整合操作校准。事实条数、图路径跳数、术语生僻程度和题面长度不能单独决定难度。允许一种方法跨越相邻难度，需说明实际增加的求解要求。

## 通用设计原则

以下八条适用于三个难度，不能以提高难度或凑足数量为由放宽。

1. **从明确的事实目标出发。** 先确定要查明哪个实体、属性、关系或条件下的结论，再形成问题。问题应能通过事实检索与证据整合回答，避免主观评价、开放建议和没有判定标准的讨论。
2. **根据证据结构设计问法。** 直接事实适合直接查询；明确关联的事实适合关系连接；有依据的多个候选适合条件筛选或比较。不能为凑难度拼接无关事实，也不能只因图中有路径就认定问题成立。
3. **题干完整定义任务。** 明确主体、关系、作答范围和影响答案的必要条件。按需要写入物种、人群、时间和实验情境，不依赖出题者私下看到的材料。必要选项和情境应完整包含在实际交给 Planner 的公开问题文本中；不使用没有公开定义的“上述材料”“情境 S”等指代。无需把答案证据写入题干。
4. **用现实条件限定答案。** 用明确的物种、疾病亚型、实验条件或公开比较集合限定任务，不用隐藏候选集、检索结果或数据库覆盖定义答案。更换可靠来源后，问题含义和答案判定标准应保持一致。
5. **事实和推断不超过证据。** 区分直接事实、关联、因果和机制。组合关系时检查实体、方向和条件一致；两个关系能连接，不代表医学推断成立。禁止凭空补充关键前提。
6. **答案要求与可证明范围一致。** 单答案题需要区分其他合理答案的条件；多答案题明确举例还是完整列举，并说明必要精度、单位或解释范围。“全部、唯一、最常见、最高”等要求必须有相应依据。局部材料中只找到一个答案，不代表现实中答案唯一。
7. **难度来自必要的检索与整合。** 中等和困难题应确实需要关系连接、条件交叉或候选比较。不靠遗漏条件、生僻措辞或冗长背景制造难度，不提前透露本来需要查明的答案或关键中间结论。选择题可包含正确选项，判断题可包含待判断命题，但不能标示结果。接受客观有效的短路径，据此重新评估难度，不强制 Planner 绕路。
8. **分别检查客观可回答性和工具可求解性。** 客观成立不代表当前知识源足够；图中能查出结果也不代表题目客观正确。确认 Planner 可用工具能够取得必要依据，且有明确完成条件。未知时标记待核实，不宣布通过；材料不足时补证据、改设计或放弃候选。检索失败不等于事实为假。

## 本项目的任务与证据约束

起草问句时，先写出读者答全它必须交付的内容，再用原文核对每一项。问“整个集合有哪些成员”应把题中已知的成员也计入答案；若只想考其余成员，就在题干中把已知成员排除。只有证据界定了集合，才能要求列全或指定数量。例如材料只列举一项试验观察到的两种反应，不能据此问某种干预“有哪些反应”并把这两种当作完整答案。把试验条件写进题干后，仍需确认材料支持条件内的完整性。

连接事实时，把问句中的代词换回实体名称，读一遍谁对谁做了什么。若原文说“A 招募 B，随后形成 C”，问句应保留这个方向与顺序。能用“谁使 A 稳定”一次答全的问题，就直接问稳定者。若目的是考筛选，可以先要求列出有明确边界的集合，再识别其中符合条件的成员，并为两部分分别写出答案。同一摘要可直接读出两项答案时，按实际整合工作定级。

提交同批候选前，把每题缩写成“要查什么、要交付什么”。如果三题分别问成员、成员的作用、成员及其作用，优先保留最符合目标难度且能独立使用的一题。共用实体或来源的题仍可并存，只要各自回答不同的信息需求，并且解决其中一题不会顺便答全另一题。

- 生产面向 query-planner 的客观生物医学知识查询。机制、相互作用和关系链等示例体现查询风格，不自动构成合格模板；“完整机制”等开放范围必须收紧到有证据支持的明确任务。
- 设计阶段仅使用输入支持的事实，候选答案须经过后续独立验证。可以组合事实，但需说明关系及适用条件，不能凭背景知识补造材料中没有的关键结论。
- 保留物种、人群、时间、剂量、实验条件、关系方向和证据强度。不能把关联链当因果链，也不能无依据地跨实验情境推断。
- 直接考察现实中的生物医学事实，不以“数据库记录了什么”“当前检索证据是否支持”作为核心任务。来源、内部候选列表和检索覆盖不能定义答案范围；必要实验情境应公开表达。
- 不得添加材料未支持的条件来强行获得唯一答案。公开比较集合可以限定任务，但集合及作答要求必须明确，不能暗示结果适用于集合之外。

## 批次与考点多样性

根据任务用途比较已有题目的考点、条件和解题操作。需要覆盖多样性时，避免只换措辞重复同一设计；用于练习、平行测验或难度对照时，可以按要求重复考点，并说明重复用途。

答案相同不自动意味着重复，答案不同也不自动意味着考点多样。不自行设定题型、考点或难度配额。

## 工作方法

从材料中挑选一个适合目标难度的考点，列出候选答案、必要公开条件以及支撑它的事实。按对应难度的方法形成提问意图和可供后续写作的题面草案。

逐题回答以下四个检查问题，不能用内部设计说明替题干补条件：

- 只给实际公开题干，是否明确知道要查什么、回答到什么范围？
- 换一个可靠来源，问题的含义和正确答案标准是否仍然成立？
- 每个关键结论和必要的组合推断是否有依据，合理替代答案是否已考虑？
- Planner 能否通过可用检索操作取得依据，并达到明确的完成条件？

检查是否有客观有效的短路径。存在时接受其解法，并据此重新分级或选择其他任务，不添加无关干扰。

材料不足时返回具体缺口，例如缺少比较对象、条件下的关系或答案唯一性依据。不要为达到数量强行生成，不静默降低目标难度。若任务允许降级，可同时提出明确标注的低难度替代方案。

## 设计交付

设计结果应让题面写作者和审核者理解：

- 语言、题型、目标难度、工具环境及尚待确认的假设；
- 考点、提问意图和题面草案；
- 候选答案及可接受变体，按题型说明答案类型、数量、精度或解释要求；
- 支撑事实及各自用途，必要公开条件；
- 简短的检索与整合需求、完成条件、合理替代答案和有效短路径检查结果；
- 是否可继续生成，或仍缺少什么材料。

这些是设计说明要求，不是已接入应用的新 JSON schema。若调用方指定结构化输出格式，遵守该格式；不要擅自添加不支持的字段或编造事实来填满字段。应用集成需要为材料不足和设计说明提供明确承载位置。

未指定难度时，设计者选择的标签是暂定评估，不自动升级为用户要求的发布门槛。明确区分任务要求和模型建议，并把已接受的要求传至写作和发布审核。当前实现尚未完整承载这些交接信息。

## 交接与质量边界

题面写作必须保留设计中的必要条件和认知要求。不能通过补充提示提前完成原定考察的操作，也不能为了简洁删除条件；设计已明确作为已知条件的中间结论可以公开提供。答案解释只说明受支持的答案，不扩展到未验证的机制或临床意义。

审核应依据实际题目判断难度和可回答性，不直接采用设计者的自报标签。措辞问题可在保留设计的情况下重写；考点、证据或答案范围有缺陷时回到设计或材料阶段。

这份 skill 的文字完整性不等于生成稳定性。后续需用固定材料在三个难度下重复生成，分别检查客观正确性、题干自包含性和 Planner 可求解性，再记录难度符合率、条件遗漏、答案泄漏和重复考点。元数据导出及训练标签不属于本 skill 的当前任务。
