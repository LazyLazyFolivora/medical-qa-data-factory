# 从已知内容提出值得检索的问题

我们在造检索动作选择器的数据集。读者只会看到题干，没有看过后台材料。题目让读者弄清一个生物医学事实、关系、差异或有边界的解释；检索负责找到答案。既需要少量直接查询的题，也需要连接多份材料的题，不为难度标签添加无关步骤。

## 先决定问什么

先用一句话说清：一个不知道答案的人，为什么会问这个问题，他想弄清哪项关系？然后检查材料能支持什么。不要从现成数字、表格列名或实验清单倒推题目。

专业条件可以自然出现在题干中，例如物种、疾病、变异、组织或干预；这些条件应有助于理解知识疑问。题干不是实验记录：若必须堆上精确补充时长、餐后时点、样本分层和测量终点，才把某次观测变成唯一答案，就应重新选择信息需求。不能删掉条件后把局部结果当普遍规律。

默认任务不包括单项论文或试验的结果阅读题。即使把“数值是多少”改成“有何差异”，把试验名换成实验条件，也没有改变这类题的本质。只有用户明确要求研究型问题时才围绕指定研究出题；主 agent 的建议不是这样的用户要求。

可选择的方向包括：实体的确定属性；两个对象在某一维度的差别；一个现象的已知解释；连接几项证据才能回答的具体关系。单篇来源、简单问题和数值答案本身都可以合格；关键是疑问独立成立，证据支持实际答案。

## 再形成题干与答案

1. 找到支撑核心关系的原句，保留主体、条件、方向和程度。图谱边、研究摘要和旧答案只能提供线索，不能补原文没有的机制。
2. 用自然问句表达一个中心疑问。多个方面只有共同解释这个疑问时才组合；不把“属性是什么”和无关的机制问题拼在一起。
3. 给出原文支持的简短答案。跨来源时逐项保留各自对象与条件，说明能建立的联系；并列出现不是因果，不同条件下的结果不能直接比数值优劣。
4. 最后只读实际题干和答案：语义是否一致？动词是否错误地支配了后面的并列对象？是否先把答案或未经证明的机制写进问题，再要求解释它？不能在脑中替题干纠错。

题干应包含会改变答案的必要条件，但不必把答案证据写进题干。设计说明、public_scope 和风险备注不能补足读者看不到的背景。用领域边界限定回答，不用“当前找到的全部材料”定义完整集合。可提有意义的非穷尽问题，不能把几个例子称为全部。

来源对大类对象的机制描述不自动适用于每个亚型；分类定义不是机制归属证据。“未发现证据”不等于不存在，“可能”不等于确定，观察相关不等于解释原因。解释应回答有据的环节，不编唯一原因、贡献比例或普遍适用性。

## 修订不是无限补条件

有 revision_context 时，先读 previous_candidate 和具体反馈，再看原文。旧答案、评审和 design_instruction 都可能错，不要求维护它们。

- 原问题有意义，仅答案有错：保留原 question_intent，只修答案中的具体断言和相应设计说明。先看 repair_issues.target；proposed_answer 或 blind_answer 的问题，不自动变成题干问题。例如机制答案漏了“可能”，应恢复答案限定，不能改问“原文对此有何确定性描述”，也不能把待回答的机制塞入题干让读者确认。只有另有具体的题干缺陷，才修题干；普通语言润色不是必须重开选题的理由。
- 原问题有意义，但材料只覆盖一部分：需要补证。返回空 hypotheses，明确缺哪一项关系、比较或条件；不要改问已有的一次观测来绕过缺口。
- 原问题只能靠某次实验的身份或整套流程才成立：需要重新选题。返回空 hypotheses，说明旧方向为什么不适合，并指出材料中可继续探索的领域关系。不要把加上人群、时点、剂量当作自动修复。

修订结果也要通过上述选题检查；评审给出的 revised_question 不是已获准的模板。不通过时可以不产题，不能为了交付非空数组把不合适的题修成另一个不合适的题。

## 输入与交付

按调用方 schema 输出，不自行添加字段或执行工具。候选答案仍待后续核验，不能声称已发布或已独立验证。

- input_mode=source_passages：直接使用给定原文；evidence_basis 填 source_passages，candidate_claim_ids 填 []，discovery_anchor_ids 引用提供的原文锚点。
- 事实模式：只引用实际提供的事实及其证据 ID。
- research_context 指定需要回答的疑问和待核对边界，不能覆盖原文或允许不合格题型。
- 有 fact_selections 时，observation 写原文观察，information_gain 简述读者的疑问及必要检索联系；无需长篇推理。
- 非空 hypotheses 必须有非空且有据的答案；不能支持时返回空 hypotheses 和具体 insufficiency_reason。
- 一个解释的互补部分合成 proposed_answer_values 中的一个完整字符串；多个独立对象才分项。
- 修订返回一个新候选。实际数量、格式遵循调用方要求，不编造内容补齐数量。

补充的 [事实选择参考](references/fact-selection.md) 用于自然表达；简单、中等、困难参考用于探索不同检索需求，不改变上述选题与证据要求。难度由后续模块独立判断，不因简单而丢掉好题，也不把术语复杂当困难。
