# 当前应用契约与接入边界

此说明对应当前 `generation/fact_exploration.py` 和 `generation/objective_question_contracts.py`，是接入记录，不代表下述缺口已经修复。

## CandidateClaim 的承载方式

| 字段 | 使用原则 |
|---|---|
| `subject` | 明确主体；有依据时统一别名，不丢物种、亚型或变异区别 |
| `predicate` | 明确关系及方向，保留关联、观察等语义，不能偷换成更强关系 |
| `object_or_value` | 明确对象或数值；保留必要单位和比较含义 |
| `qualifiers` | 保存影响含义的条件；当前为字符串键值映射，保持值可读，不加入模型猜测 |
| `claim_strength` | 表达来源支持的陈述性质及限制，不当作全局真实性评分 |
| `polarity` | 与完整谓词和对象共同表达 POSITIVE、NEGATIVE 或 UNKNOWN，避免双重否定或把未知当否定 |
| `supporting_anchor_ids` | 只引用可见且实际支持该陈述的锚点，至少一条 |
| `contradicting_anchor_ids` | 仅引用实际可比且支持相反结论的可见锚点；不要把条件不同直接当冲突 |
| `status` | 保持 PROPOSED，不能自行改成已验证 |
| `claim_id`、`extraction_model_version` | 遵守宿主契约和身份管理；模型版本由当前宿主在接收后写入 |

不把新的诊断对象或关系分组结构塞进未声明字段。条件缺失、组合兼容性和材料不足需要明确的诊断承载；实现前不宣称系统已保存这些信息。

## 已知接入缺口

- `CandidateClaimBatch.claims` 当前要求至少一条，无法正常表达“成功阅读但没有可用事实”。接入此 skill 时需为该结果提供独立状态或允许空集合；不能要求模型编造事实以满足 schema。
- 当前模型 payload 提供原始材料和各材料的 anchor ID 列表，但不显式提供每个 anchor 的引文及范围。多锚点材料可能无法准确对应，应补齐映射；仅知道 ID 属于某材料不等于知道它支持哪句话。
- 当前宿主显式检查支持锚点是否可见，但仅有引用合法性检查不能证明语义支持；矛盾锚点也需要相同的引用与语义核查。
- 后续 `claim_groups` 按共同材料分组。这是来源分组，不保证组内事实构成可组合关系或在同一实验条件下成立。
- 当前调用使用任务范围的实体解析结果。即使身份已标为 RESOLVED，材料中的物种或对象仍需核对，不能把宿主默认条件强加给原文。

## 审阅与试用

先用提取示例和真实材料检查条件保留、否定与不确定性、引用支持、重复与冲突处理。检验应对照原始材料，不只检查 JSON 字段齐全。之后再调整代码承载和接入方式。
