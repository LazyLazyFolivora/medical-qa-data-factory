# 发布审核的运行时接入边界

已有 `release_review_subagent.py` 会读取本 skill 全文并使用内容摘要生成版本标识。因此本次更新会影响后续审核提示，但不会自动新增输入、响应字段或校验逻辑。

## 两阶段职责

1. `public_question_audit` 只接收问题 ID 和文本，不看答案、契约或证据。检查任务含义、自包含、来源独立、实体及数量要求。缺少隐藏答案是设计上的隔离，不是该阶段的失败。
2. `answer_evidence_audit` 接收已记录的公开审核结果、问题、冻结契约、答案验证结果和独立证据。核对真实题面与契约、答案支持、数量、冲突与关系强度，不能改写题目后审新版本。

最终 `merge_objective_audits` 由程序执行，检查两阶段结果和已有布尔门禁。公开阶段通过不代表整体可发布。

## 新要求与现有输入的差距

- 当前没有显式传入 Planner 工具、知识源可达性和目标难度，不能从 provider 名或上游通过状态推断这些信息。
- 完整审核新增的 Planner 可求解性在缺少环境信息时应为不确定。按本 skill 严格执行，当前答案审核可能因此阻止发布；这是输入缺口，不代表运行时已完成对接。
- 公开阶段可以判断查询目标和范围是否明确，但不应尝试推断未知环境里的可求解性。
- 当前响应 schema 没有独立 Planner 审核和难度字段，可用已允许的 verdict、primary_reason、secondary_reasons 报告相应阻塞。不要直接返回主文件的 standalone 扩展示例作为阶段响应。
- 未来接入需显式承载环境和设计要求，并同步最终门禁；目前新增要求仍依靠模型返回非 PASS verdict，不是新增的确定性布尔校验。
- 当前答案审核输入没有题面生成器的 `concise_explanation`，不能宣称解释已审。若解释要随数据发布，应加入对应审核输入。
- 现有流程没有针对不同缺陷自动分派修复的完整机制。skill 的回退建议是诊断要求，不是已实现的重写或补查工具。

接入检验应覆盖：公开阶段不因隐藏答案缺失而失败；完整审核因环境缺失保持不确定；语义漂移、答案提示、请求难度不符能阻止通过；修复稿重新审核而不覆盖原失败结论。
