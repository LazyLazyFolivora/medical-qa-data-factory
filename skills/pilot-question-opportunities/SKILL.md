# 从材料发现出题机会

阅读概览、图谱线索和实际补查结果，提出最多四个有意义的信息需求。覆盖面来自不同的知识问题，不要求每个实体都能产生全部类型或难度。

每个机会说明：用户想查清什么、答案需要哪些事实、这些事实怎样连接、已有依据和还缺什么。“资料有这个字段”不是需求的价值；应说明读者能了解何种特征、关系、差异或现象。

先填三个思考位置，再写需求：

- bridge_fact：材料已经明确支持的一个关系，写出两个端点和来源原句。
- next_entity：接下来需要了解的具体对象；无需补查时写“无”。
- lookup_property：要查该对象的哪一个具体属性；已有支持时写“已有材料足够”。

有明确实验观察时先考虑其中已识别的作用对象，之后才探索只有泛化互作边的邻居。
邻居列表的排列顺序没有生物学意义。不要因为一个名字排第一就选它。
补查应带来新信息：输入已含种子 UniProt 概览，再请求同样概览不算补查。

例如 bridge_fact 为“R 过表达抑制 A 诱导的表型（附原句）”，next_entity 为 R，
lookup_property 为“R 在该生物过程中的一般功能”。
实际动作应是 `tool=uniprot, query=R`，不要再查 A。
primekg 和 uniprot 的 query 都是一个实际实体名或基因符号，不是“谁和谁互作”这样的句子。
pubmed 才接收关键词或布尔搜索表达式。自我结合与形成衣壳不是同一结论，
跨论文连接时分别保留，不能只因为都含 assembly 就合并。

## 从可回答的小问题延伸

先保留一项已有明确事实答案的需求，再尝试一项只缺一个具体连接的信息需求。
较好的补查目标是“这个已被实验识别的对象是什么、有什么功能”，而不是
“两种现象之间是否存在尚未发现的完整机制”。用已有材料中的具体观察作为起点。

完整示范（以下 A、B、R、C 均为假想对象，不能用于实际答案）：

1. 读到实验：在细胞 C 中，A 过表达促进某种明确的死亡表型；B 过表达抑制该表型。
2. 直接需求：什么蛋白的过表达能抑制 A 诱导的该表型？已有答案 B。
3. 延伸需求：举出一个有该抑制效应的蛋白，并说明其通常怎样调节对应生物过程。
   这是理解实验干预对象的功能背景，答案需要“实验识别 B”和“B 的功能”两项事实。
4. 补查：查 B 的规范功能注释。若不知道调控方向，就不要写进问题前提。
5. 若查到 B 的相关功能，可形成“在细胞 C 的该表型实验中，举出一种过表达后
   能抑制 A 诱导表型的蛋白，并说明它在对应生物过程中的一般作用”。实际题干
   使用明确的细胞、表型和过程名称。答案先给 B，再说明功能。
6. 两项事实不证明这个实验里 A 一定直接结合 B，答案不添加这条机制。
   如果同一篇实验摘要已包含 B 的功能，则它仍可能是简单题。

另一种连接：材料报告 A 与 B 互作，且 B 的另一项属性有证据。可以围绕
自然的功能条件要求举出一个互作对象并说明其属性。一个互作名单不支持“唯一”
识别；不要随意凑候选名字制造选择题。若互作关系只有无条件的图谱边，补查它
的实验含义通常比扩展上百个邻居更有价值。

这个方法可用于干预对象、编码对象、组成成分、作用靶点等，不限定蛋白领域。
优先选能解释当前观察的属性；给对象追加无关的染色体或家族问题不构成有意义的连接。

## 提问操作与补查

选择适合材料的提问操作：

- 直接查询：明确一个属性或关系，找到直接证据即可回答。
- 关系连接：先确定中间对象，再查它的属性。说明为何需要中间步骤。
- 条件筛选：分别核对多个条件，判断候选是否符合。题干的候选范围应自然合理。
- 比较：围绕一个有意义的维度取得可比材料；同一注释已给出的对比仍可能是简单题。
- 有边界的解释：围绕指定现象解释已获支持的环节，避免泛问“完整机制”。

先画出简短的事实依赖，再决定是否值得补查。允许有效短解，不要求答题者沿出题时的路径走。

如 A 与 B 互作、B 参与过程 C：可以探索“与 A 互作且参与 C 的对象”或查询 B 的作用，但不能推出 A 调控 C。若题干问唯一对象，必须有充分区分条件；局部邻域中的唯一节点没有这种证明力。也可以用明确的例子型要求。

挑一到两个最有希望而缺关键事实的机会继续查，每次查询明确补哪个缺口。已有材料支持的简单题仍可保留。若文献只记录核仁定位并另述肿瘤细胞中的胞质定位，不擅自将前者改为“正常细胞”；比较必须有真实可比的两侧。

补查应改变已有检索：PubMed 长查询为空时先用实体短查询；已有相关 PMID 时直接读取摘要。如果缺口是某个互作蛋白的功能，就查询该蛋白的 UniProt 或图谱邻域，而不是继续同时搜索种子、疾病、机制、互作等全部词。优先选材料中有具体线索的对象，外部知识仅能作为待验证线索。

pubmed_fetch 只返回摘要。若该 PMID 摘要已在输入里，重复调用不会获得全文；需要结构细节或全文实验条件时应把这类需求记录为当前工具不能补齐，或寻找其他相关文献。

举例：已知 A 与 B 互作，但不知道 B 的功能。下一步查 B；拿到功能信息后才能判断能否形成关系连接问题。不能将“查不到 B 的功能”作为这道客观事实题的标准答案。

机会保留原始片段及 source 标识，指出图谱与文献的分工。遇到研究条件或结论不一致，先缩小到明确的实验情境或补查。候选不是已验证题目。
