# 生物医药生成问题的题型与语言验收规范

> 状态：问题内容设计与验收依据  
> 受众：问题生成、Prompt、数据、评测和人工审核人员  
> 更新日期：2026-10-25  
> 适用范围：`ValidatedTask -> QuestionVariant -> QuestionSpec`

## 1. 这份规范解决什么问题

本文规定生成的问题应该分成哪些类型、每类问题怎样组织语言，以及什么样的问题不能进入训练数据。

这里的“题型”不是模型语气，也不是 KG relation 名称。一个问题应分别记录三个维度：

1. **推理结构**：回答问题需要怎样的检索或组合；
2. **生物医药意图**：问题在药物、靶点、疾病、通路或证据层面实际询问什么；
3. **语言风格**：面向研究人员、医学学习者还是普通搜索用户表达。

三个维度必须分开。否则会出现 `single_fact`、`risk_decrease`、`patient_question` 混在同一个 `question_type` 字段里的问题，既无法控制数据分布，也无法判断措辞是否保持了原任务。

## 2. 总体结论

第一版应以**结构明确、答案可验证、适合 Planner 检索**的问题为主，不追求开放式医学问答。

推荐的第一版核心题型是：

1. 单关系实体定位；
2. 带约束的唯一实体选择；
3. 隐藏中间实体的两跳问题；
4. 显式给出中间线索的两跳问题。

以下类型应暂缓，直到对应的 `AnswerForm` 在候选生成、答案执行、完整性验证、Writer、Verifier 和导出链路中全部通过验收。仅在枚举中已经存在某个 answer form，不代表该题型已经可以生产：

- 开放式机制解释；
- 自由文本“为什么”；
- 临床诊断和治疗建议；
- 无边界的“有哪些”；
- 比较优劣、疗效排序和风险大小排序；
- 依赖最新医学共识但没有固定时间范围的问题；
- boolean、count 或 set 答案，但第一版生产链路尚未完成相应端到端验收的情况。

`insufficient` 不是一种语言题型。它是同一自然问题在指定 evidence environment 下不可完成的任务状态，不应通过“根据现有资料无法判断……”这类措辞直接泄漏给 Planner。

### 2.1 有限信息生成 完整世界成立

所有题型共同遵循：

> **问题可以从有限 evidence slice 中发现，但必须适配定义好的完整验证世界。**

设生成时看到的证据为 `S`，Planner 可访问的完整冻结世界为 `W`，则 `S` 是 `W` 的子集。Writer 可以根据 `S` 提出题面，但 gold answer 必须通过 `Evaluate(question, W)` 得到。

因此：

- `S` 中只有一个疾病，不代表“哪种疾病”是单答案题；
- `S` 中只有一个蛋白，不代表“哪种蛋白”是单答案题；
- 如果 `W` 中存在多个答案，必须增加由真实证据支持的有效限定、改成集合题，或者拒绝候选；
- 不允许使用“在当前证据范围内”“根据这组资料”等措辞把局部采样范围包装成自然语言限定；
- 所有“唯一”“全部”“没有其他答案”都只能相对于版本化 `ValidationWorldSnapshot` 声明。

这里的完整世界是工程上的 operational world：固定 KG、固定文献索引、固定工具能力和时间边界，不声称覆盖整个人类医学知识。

### 2.2 本规范实际要生成的问题

本规范的第一版目标不是生成宽泛的开放医学问题，而是生成以下性质的问题：

- 问题有一个明确的生物医药信息需求；
- `LogicalQuery` 可以在完整验证世界执行；
- 单答案题的 world answer set 严格只有一个实体；
- 题面包含使答案成立所必需的真实语义约束；
- 问题仍需要 Planner 检索，题面没有直接泄漏答案；
- 语言像研究人员提出的问题，而不是数据库查询。

为了展示最终产物，下面定义一个验收 fixture。只有在 fixture 的完整世界 `W_fixture` 中 evaluator 确认以下结果时，这些题才算正例：

```text
HER2 protein --encoded_by--> ERBB2 gene
ERBB2 gene --located_on--> human chromosome 17

answer(encoded_by(HER2)) = {ERBB2}
answer(located_on(encoded_by(HER2))) = {chromosome 17}
```

对应的四种目标问题如下：

| Reasoning type | 问题 | Gold answer | 为什么可以成为正例 |
|---|---|---|---|
| `entity_lookup_1hop` | `HER2 受体由哪个基因编码？` | `ERBB2` | 完整世界中编码关系的答案集合为单元素 |
| `constrained_entity` | `哪个基因既编码 HER2 受体，又位于人类 17 号染色体？` | `ERBB2` | 两个正式 query 条件的交集为单元素 |
| `relation_chain_hidden` | `编码 HER2 受体的基因位于哪条人类染色体？` | `17 号染色体` | 隐藏中间基因后，完整两跳终点并集仍为单元素 |
| `relation_chain_explicit` | `HER2 受体由 ERBB2 编码；ERBB2 位于哪条人类染色体？` | `17 号染色体` | bridge 可见且固定 bridge 的第二跳答案为单元素 |

这些是“任务 + 世界 + 答案集合”共同构成的正例，不是因为句子看起来合理就自动合格。生产环境必须在实际 `ValidationWorldSnapshot` 中重新执行，不能直接把 fixture 中的医学事实当作 gold 导入。

相比之下，以下不是本规范第一版要生成的单答案题：

- `阿司匹林作用于哪种蛋白？`
- `与 BRCA1 相关的蛋白参与哪种生物过程？`
- `某药物靶点所参与的通路与哪种疾病相关？`
- `与阿司匹林相关的疾病是什么？`

它们的问题方向可以启发候选发现，但完整世界中的答案通常是多个。没有进一步、真实且可执行的约束时，应改成经过完整性验证的集合题或直接拒绝。

正式正例建议保存为一个完整 case，而不是只保存一句话：

```yaml
question: 编码 HER2 受体的基因位于哪条人类染色体？
reasoning_type: relation_chain_hidden
logical_query_id: query.example
generation_slice_id: slice.example
validation_world_snapshot_id: world.example
slice_answer_ids:
  - chromosome-17
world_answer_ids:
  - chromosome-17
expected_cardinality: one
verdict: accepted
```

## 3. 问题分类模型

建议每道题使用以下字段：

```python
class QuestionContentSpec(ContractModel):
    reasoning_type: Literal[
        "entity_lookup_1hop",
        "constrained_entity",
        "relation_chain_hidden",
        "relation_chain_explicit",
    ]
    biomedical_intent: str
    answer_form: Literal["entity"]
    answer_entity_type: str
    route_visibility: Literal["direct", "bridge_hidden", "bridge_explicit"]
    language_profile: str
    required_constraints: dict[str, str]
    forbidden_disclosures: list[str]
    generation_slice_id: str
    validation_world_snapshot_id: str
```

其中：

- `reasoning_type` 决定 Planner 需要解决的结构；
- `biomedical_intent` 决定可以使用什么关系词；
- `answer_form` 决定问句结尾应该寻找什么；
- `route_visibility` 决定中间实体能否出现在题面；
- `language_profile` 只改变表达方式，不改变上述任何字段。

## 4. 第一版核心题型

### 4.1 单关系实体定位

**定义**：从题面给出的锚点实体出发，通过一个明确关系定位唯一答案实体。

```text
Seed --relation--> Answer
```

**适用场景**：

- 药物 -> 靶点；
- 基因或蛋白 -> 通路；
- 疾病 -> 表型；
- 药物 -> 已研究适应症；
- 药物 -> 禁忌情况；
- 暴露或药物 -> 有方向的风险关联疾病。

**推荐语言结构**：

```text
[锚点实体] + [证据允许的关系表达] + [哪种答案类型]？
```

**句式候选**：

- `BRCA1 参与哪条 DNA 修复通路？`
- `观察性研究显示，阿司匹林使用与哪种癌症的风险降低相关？`
- `哪种情况被列为华法林的禁忌证？`

这些只是可进入验证的句式，不是脱离任务上下文即可认定的合格问题。只有完整 `ValidationWorldSnapshot` evaluator 证明答案唯一，并且 evidence 支持相应的 `参与`、`风险降低相关` 或 `禁忌` 语义时才合格。

**不合格示例**：

- `阿司匹林和哪种实体有关？`：答案类型和关系语义不明确；
- `阿司匹林与哪种疾病有关？`：`有关` 过宽，可能对应适应症、风险、禁忌或一般关联；
- `阿司匹林已知作用于哪种蛋白？`：完整世界中通常可能存在多个蛋白，局部 evidence 中只看到一个不能证明唯一；
- `在当前证据范围内，阿司匹林使用与哪种癌症的风险降低相关？`：用局部证据范围掩盖全集基数，且范围不可复现；
- `PrimeKG 里阿司匹林的 tail 是什么？`：实现术语泄漏；
- `阿司匹林会导致哪种癌症？`：把关联升级为因果；
- `阿司匹林能治好哪种癌症？`：把研究或关联升级为疗效结论。

### 4.2 带约束的唯一实体选择

**定义**：答案实体需要同时满足两个或多个明确条件，但最终答案仍为一个实体。

```text
Answer satisfies Constraint A AND Constraint B
```

该题型比普通单跳题更适合训练 action selection，因为 Planner 必须判断先验证哪个约束，或怎样缩小候选集合。

**推荐语言结构**：

```text
[候选答案类型]中，哪一个/哪一种同时满足[条件 A]和[条件 B]？
```

也可以写成：

```text
哪种[答案类型]既[条件 A]，又[条件 B]？
```

**句式候选**：

- `哪种药物既靶向 ERBB2，又被研究用于 HER2 阳性乳腺癌？`
- `哪种蛋白既与目标疾病相关，又参与指定的 DNA 修复通路？`
- `在已给定的候选范围内，哪种疾病同时符合该基因关联和表型约束？`

最后一个例子只有在候选范围作为正式 query filter 提供时才能使用；不能靠题面中的“给定范围”掩盖一个实际上没有定义的集合。

这些句式本身不保证单答案。设满足条件 A 的全集为 `C1`，满足条件 B 的全集为 `C2`，单答案题只有在完整验证世界中 `|C1 ∩ C2| = 1` 时才成立。生成时碰巧只观察到一个交集实体不算通过。

**不合格示例**：

- `哪些药物能治疗乳腺癌？`：开放集合且“能治疗”可能夸大证据；
- `最好的药是什么？`：缺少比较指标、人群和时间范围；
- `哪种药比较相关？`：关系和比较标准均不明确；
- `哪种药同时满足系统里的两条边？`：实现结构泄漏。

### 4.3 隐藏中间实体的两跳问题

**定义**：问题的答案依赖两条连续关系，但题面不直接给出中间实体名称。

```text
Seed --r1--> Hidden Bridge --r2--> Answer
```

这是第一版可能有较高 Planner 价值的题型，但也是最容易产生多答案的题型。Planner 需要先发现 bridge，再围绕 bridge 查询下一跳；每一跳的分支都会扩大最终候选集合。

完整世界中的答案集合必须按以下方式计算：

```text
B = all entities reachable from Seed by r1 in W
A = union of all entities reachable from every b in B by r2 in W
```

只有 evaluator 未截断且 `|A| = 1` 时，才能生成使用“哪条”“哪种”或“哪个”的单答案题。不能只验证生成器选中的一条 `Seed -> Bridge -> Answer` 路径。

**推荐语言结构**：

题面应描述组合语义，而不是描述“走两跳”：

```text
[锚点实体]所[关系 1]的[中间类型]，进一步[关系 2]到哪种[答案类型]？
```

自然表达时可以省略“进一步”，但必须保留组合关系的语义。

**默认应拒绝的宽泛候选**：

- `阿司匹林所作用的蛋白参与哪条信号通路？`：阿司匹林可能对应多个蛋白，每个蛋白又可能参与多条通路；
- `与 BRCA1 相关的蛋白参与哪种生物过程？`：相关蛋白和生物过程通常都不是单数；
- `某药物靶点所参与的通路与哪种疾病相关？`：药物、靶点、通路和疾病均未形成可证明的唯一约束。

这些问题只有在完整世界执行后答案并集严格为 1，且题面包含所有使其唯一的真实语义约束时，才可能改写为合格问题。现实数据中大概率应改为集合题或直接拒绝。

**不合格示例**：

- `沿两条连续关系从阿司匹林出发会到达哪种疾病？`：描述数据库遍历，不是生物医药问题；
- `顺着这组资料继续查，最后指向什么？`：关系语义和答案类型都不明确；
- `阿司匹林经过 PTGS1 后关联到什么？`：如果 PTGS1 被定义为隐藏 bridge，这会降低任务难度并泄漏路线；
- `阿司匹林通过某蛋白导致哪种疾病？`：不必要地升级为因果。

### 4.4 显式中间线索的两跳问题

**定义**：问题仍需要组合两条证据，但题面明确给出中间实体或中间条件。

```text
Seed --r1--> Named Bridge --r2--> Answer
```

它与隐藏 bridge 题必须分开标注。显式 bridge 通常更容易，适合生成难度梯度或对照组。

**推荐语言结构**：

```text
[锚点实体]作用于[中间实体]；该实体参与哪条[答案类型]？
```

或使用一个自然的定语从句：

```text
[锚点实体]靶向的[中间实体]与哪种[答案类型]相关？
```

**句式候选**：

- `阿司匹林作用于 PTGS1；PTGS1 参与哪条生物通路？`
- `药物 X 靶向 EGFR；EGFR 与哪种疾病相关？`

真实题面必须使用具体药物名称替换 `药物 X`。只有 query 明确允许暴露 bridge 时，才能使用此题型。

显式给出 bridge 只减少第一跳的不确定性，不保证第二跳唯一。对固定 bridge `b`，仍必须在完整世界计算 `A = N_r2(b)`；只有 `|A| = 1` 时才可使用单数问法。

**不合格示例**：

- `答案路径是阿司匹林、PTGS1 和某疾病，请补全疾病。`：直接暴露训练结构；
- `根据 evidence-123 和 edge-456，答案是什么？`：内部 ID 泄漏；
- 把本应隐藏的 bridge 写进题面：任务语义发生变化，不能只当作措辞变体。

## 5. 暂缓题型

### 5.1 开放列表题

例如：

```text
与阿司匹林相关的疾病有哪些？
```

该题需要证明完整枚举范围，并明确 snapshot、过滤条件和集合答案语义。否则无法区分“漏答”和“数据源中没有”。虽然现有 `AnswerForm` 已包含 `set`，但在 completeness evaluator 和端到端 set 验证通过前，不进入正式数据。

### 5.2 是非题

例如：

```text
阿司匹林是否与前列腺癌风险降低相关？
```

这种问法可以用于证据意图审核，但实体答案任务不能静默转成 boolean。虽然现有 `AnswerForm` 已包含 `boolean`，仍需补齐明确的正反例构造、反事实验证和端到端导出验收后才启用。

### 5.3 数量题

例如：

```text
某药物有多少个已知靶点？
```

只有当 snapshot 完整性、去重规则、分页和截断都可证明时才允许。虽然现有 `AnswerForm` 已包含 `count`，在这些条件未验证前，数字只是当前查询返回量，不是可靠答案。

### 5.4 开放式机制解释

例如：

```text
阿司匹林为什么可能影响癌症风险？
```

它要求自由文本综合、因果边界和证据引用，不适合直接映射到当前实体答案和 Planner action label。可在未来作为独立任务族设计，不能混进实体检索数据。

### 5.5 比较、推荐和临床决策题

以下问题第一版直接拒绝：

- `哪种药效果最好？`
- `患者应该选择哪种治疗？`
- `哪种药副作用更小？`
- `这个检查结果应该如何处理？`

这类题需要人群、终点、比较组、剂量、时间和指南版本，且可能构成医疗建议，不属于当前数据产品。

## 6. 生物医药意图与用词

推理结构相同，不代表关系语言相同。Writer 必须根据 evidence 支持的 intent 选择词语。

| Biomedical intent | 推荐表达 | 禁止无证据升级为 |
|---|---|---|
| target interaction | 靶向、作用于、结合 | 治疗、治愈 |
| pathway participation | 参与、属于、调控 | 导致疾病 |
| association research | 相关、存在研究关联 | 导致、预防 |
| therapeutic research | 被研究用于、被评估用于 | 已获批、有效治疗 |
| risk increase | 与风险升高相关 | 一定导致 |
| risk decrease | 与风险降低相关 | 可以预防 |
| contraindication | 被列为禁忌、存在禁忌关系 | 一定产生严重伤害 |
| safety signal | 与某安全性信号相关 | 已证实副作用 |
| biomarker association | 被研究为相关标志物 | 可确诊 |

如果 evidence 只能支持一般 association，就只能使用“相关”或“存在研究关联”。Writer 不能为了让问题听起来更自然而换成“导致”“治疗”“预防”“诊断”或“机制是”。

## 7. 语言组织规则

### 7.1 一道题只保留一个主要信息需求

单一答案槽的句式候选：

```text
阿司匹林已知作用于哪种蛋白？
```

它只说明句法上有一个信息需求；如果完整验证世界中存在多个蛋白答案，仍会因 QC-004 失败而被拒绝。

不合格：

```text
阿司匹林作用于什么蛋白、参与什么通路，并可能治疗哪些疾病？
```

后一问包含多个答案槽和多种推理任务，无法对应一个稳定的 stopping condition。

### 7.2 默认顺序

中文题面优先按照以下顺序组织：

```text
锚点实体 -> 必要限定 -> 关系意图 -> 答案类型槽
```

例如：

```text
阿司匹林 + 在观察性研究中 + 与风险降低相关 + 哪种癌症？
```

整理为自然问句：

```text
在观察性研究中，阿司匹林使用与哪种癌症的风险降低相关？
```

这不是强制模板。Writer 可以调整语序，但不能删除必要限定或增加新事实。

### 7.3 独立可读

正式数据集题面必须脱离上下文也能理解。因此默认禁止：

- `这种药`、`这个基因`、`上述疾病`；
- `继续往下查`、`根据前面的信息`；
- `它`、`该实体` 等没有明确先行词的代词。

同一实体可以在一句话中使用一次规范名称，后续短距离指代必须无歧义。

### 7.4 使用自然领域语言，不描述数据结构

禁止在面向模型的问题中出现：

- PrimeKG、知识图谱、数据库、字段、节点、边；
- head、tail、ID、action type、evidence ID；
- `沿两跳`、`经过两层关系`、`最终节点`；
- `疾病实体`、`蛋白实体`、`关系记录`。

应该说“哪种疾病”“哪个蛋白”“哪条通路”，并使用真实关系语义。

### 7.5 不使用空泛关系词代替任务定义

以下词语单独使用时信息不足：

- 有关；
- 有联系；
- 对应；
- 指向；
- 影响；
- 关系是什么。

如果 query 区分风险、靶向、通路参与或治疗研究，题面必须保留这种区分。一般 association 题可以使用“相关”，但仍应明确答案类型和必要范围。

### 7.6 不增加伪造场景

除非任务本身提供，Writer 不得增加：

- 年龄、性别、症状、化验结果；
- 用药时长和剂量；
- 家属正在服药；
- 医生建议或个人诊断；
- 研究人群和研究设计。

因此，当前 `patient-caregiver` 风格中的“家人正在用某药”不适合作为通用变体。它创造了任务中不存在的事实，也把生物医药检索题变成了个人医疗场景。

### 7.7 长度与句法

推荐值而非绝对门禁：

- 中文主体通常为 12 到 45 个汉字；
- 最多一个分号或一个逗号从句；
- 一个明确问号；
- 避免“请问、请根据资料、请分析一下”等无信息前缀；
- 限定条件较多时，优先增加一个短前置状语，不要堆叠三层以上定语。

长度门禁应服务于语义完整性。不能为了满足长度上限删除 filter、population、temporal scope 或 relation polarity。

## 8. 推荐语言风格

项目定位是生物医药数据生产，第一版不应由患者问诊语气主导。

推荐三个 profile：

### 8.1 biopharma research neutral

面向药物发现、转化研究或生物信息人员。允许使用标准术语，但不出现实现词汇。

句式骨架。只用于已经通过全集基数验证的 `ValidatedTask`：

- `哪种[药物]同时满足[靶点约束]和[研究适应症约束]？`
- `[基因]相关蛋白在[必要限定条件]下参与哪条[通路类型]？`

建议作为默认 profile。

### 8.2 concise professional search

像研究人员输入检索框的短问句，保留所有必要限定。

句式骨架。方括号中的限定来自已验证 query，不能由 Writer 临时补充：

- `[药物]在[必要生物过程限定]中的蛋白靶点`
- `[基因]在[必要条件]下参与的[通路类型]`

短问句不能退化成关键词堆叠。

### 8.3 medical learner

面向具备基础医学知识的学习者，使用完整、清楚的问句。

句式骨架。它只展示学习者语气，不证明答案唯一：

- `[药物]在[必要限定条件]下作用的蛋白参与哪条[通路类型]？`

不得使用“沿两条关系”“对应哪种实体”等教学数据库术语。

普通用户或患者风格只有在下游产品确实面向这些人群时才启用。风格比例应由目标使用场景决定，而不是为了表面多样性平均分配。

## 9. 建议的首批题型分布

用于验证系统的首批 pilot 可以采用以下起始分布：

| Reasoning type | 建议比例 | 主要训练价值 |
|---|---:|---|
| `entity_lookup_1hop` | 25% | 建立基本检索和及时停止能力 |
| `constrained_entity` | 35% | 训练候选缩小和动作选择 |
| `relation_chain_hidden` | 30% | 训练发现 bridge 和连续检索 |
| `relation_chain_explicit` | 10% | 形成难度对照并测试条件利用 |

这不是长期固定比例。实际应根据 rollout transition 分布调整，避免 `continue`、`complete` 或某种 action 长期失衡。

建议另行构造 15% 到 25% 的 insufficient 环境版本，用于训练终止判断。它们复用上述自然题型，不在题面中声明“信息不足”。具体比例应根据 rollout 后的 step-level 标签分布调整，而不是仅按问题数量平衡。

## 10. 当前 Style Skill 需要修正的内容

现有 style assets 中存在一些不应继续作为正例的表达：

| 当前表达 | 问题 | 应改为 |
|---|---|---|
| `阿司匹林暴露对应哪种疾病实体？` | 节点类型和数据库语气 | 使用 evidence 支持的具体风险或关联表达 |
| `沿两条连续关系从阿司匹林出发，最终对应哪种疾病？` | 直接描述图遍历 | 用两条关系组合后的生物医药语义提问 |
| `在医学记录中与哪种蛋白相关？` | “医学记录”是空泛来源包装 | 直接说靶向、结合或相关，取决于 evidence |
| `家人正在用阿司匹林……` | 增加不存在的个人用药事实 | 使用独立、中性的实体问题 |
| `从药物继续往下查……` | 依赖交互上下文且缺少关系语义 | 明确药物与靶点、通路或疾病的组合关系 |

建议新增 `biopharma-researcher-v1`，并把它设为默认 style。现有 `layperson-search-v1`、`medical-learner-v1` 和 `patient-caregiver-v1` 可以保留，但必须清理与各自 forbidden terms 冲突的 examples。

## 11. 单题硬性验收标准

每个候选问题必须全部满足以下条件才能发布：

| ID | 验收项 | 通过条件 |
|---|---|---|
| QC-001 | 单一任务 | 只有一个主要答案槽和一个 stopping 目标 |
| QC-002 | 语义等价 | 题面可还原为同一个 `LogicalQuery` |
| QC-003 | 答案契约 | 问法与当前 answer form 一致 |
| QC-004 | 全集答案范围 | 单实体题在完整 `ValidationWorldSnapshot` 上答案唯一；generation slice 中唯一不计入通过条件 |
| QC-005 | 关系精度 | 关系用词不宽于也不强于 evidence intent |
| QC-006 | 限定完整 | query 的 filter、polarity、population 和 temporal scope 未丢失 |
| QC-007 | 无答案泄漏 | 未出现答案名称、唯一别名或被禁止的提示 |
| QC-008 | 路线可见性 | bridge 是否出现与 `route_visibility` 一致 |
| QC-009 | 无实现词汇 | 不包含图、库、节点、边、字段和内部 ID 词汇 |
| QC-010 | 独立可读 | 不依赖上一轮对话、代词或未提供上下文 |
| QC-011 | 无虚构事实 | 未增加患者、研究、人群、剂量或时间信息 |
| QC-012 | 无医疗建议 | 不要求诊断、处方、治疗选择或预后判断 |
| QC-013 | 语言完整 | 句子通顺、问项明确、无占位符和截断 |
| QC-014 | Planner 价值 | 问题确实需要目标检索结构，不可仅凭题面直接读出答案 |
| QC-015 | 生成验收分离 | 记录不同的 `generation_slice_id` 和 `validation_world_snapshot_id`，并保存两者各自的答案集合 |
| QC-016 | 不洗白局部范围 | 不用“当前证据”“这组资料”“本次结果”等措辞把局部采样变成问题语义 |

任一项失败，该 variant 被拒绝或重写。不能用自然度评分抵消 QC-002、QC-004、QC-005、QC-006、QC-007、QC-008、QC-015 或 QC-016 的失败。

## 12. 人工审核评分表

通过硬门禁后，人工审核按 1 到 5 分评价：

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 自然度 | 明显模板或数据库语言 | 可理解但略生硬 | 像真实专业用户会问的问题 |
| 明确性 | 不知道在问什么 | 基本明确但范围略宽 | 信息需求和答案类型明确 |
| 生物医药准确性 | 用词改变事实强度 | 大体正确但不够精确 | 完整保持 evidence intent |
| 检索价值 | 题面泄漏答案或无需检索 | 只需机械单次查询 | 与标注 reasoning type 一致 |
| 简洁性 | 冗长或包含多个任务 | 有少量无信息表达 | 没有多余场景且保留全部约束 |

建议发布阈值：

- 生物医药准确性必须为 5；
- 明确性和检索价值不得低于 4；
- 自然度和简洁性不得低于 3；
- 总分至少 21 分；
- 两名审核者对是否发布存在分歧时，由第三人裁决。

评分只用于通过硬门禁后的排序和人工验收，不替代确定性 answer、query 和 leakage 验证。

## 13. 推荐实现顺序

1. 把 `reasoning_type`、`biomedical_intent`、`route_visibility` 和 `language_profile` 拆成独立字段；
2. 先为四种核心题型各建立 20 个经过人工确认的正例和 20 个 hard negative；
3. 新建 `biopharma-researcher-v1` style skill；
4. 清理现有 style examples 中的数据库语言、空泛关系词和虚构患者场景；
5. Writer 从 `ValidatedTask` 的结构化槽位生成题面；
6. 增加 QC-001 至 QC-016 的确定性与模型验证，优先实现“局部一个答案、完整世界多个答案”的拒绝用例；
7. 用 pilot 分布生成问题并进行双人盲审；
8. 根据 rollout 数据调整题型比例，而不是仅优化 Writer 的自然度分数。
