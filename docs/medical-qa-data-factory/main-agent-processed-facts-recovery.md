# 已处理材料的重复理解动作恢复

## 故障

此前处理 `UNDERSTAND_FACTS is illegal in CLAIMS_PROPOSED` 的恢复只覆盖可以设计题目的场景。
在 `CANDIDATES_PROCESSING` 中已有活跃候选时，设计通常不可用；模型重复选择理解已处理材料，
仍会在重试结束后抛错。状态名称并不是动作是否可执行的充分条件，实际还取决于材料和候选产物。

## 修复

模型输出 schema 的 action 枚举现在与当前 available_actions 一致，生成时即提示合法动作集合。
保留宿主语义检查与三次修正机会；对于不能严格遵守 JSON schema 的提供方，仍由原校验阻止非法动作。

若最后一次仍要求理解事实、所有材料已经处理完、运行非终态，按当前可执行动作继续已有工作：

1. 已达到发布目标则结束。
2. 可审核则审核，可写题则写题，可验证则验证。
3. 没有活跃候选且允许设计时，使用现有候选事实设计。
4. 活跃候选尚无可用验证动作时，使用配置的来源路由补查验证资料，记录目标 hypothesis 和全面验证目的。

补查需求来自候选公开问句，不把候选答案塞进查询。恢复动作重新构建参数和输入，
不沿用非法理解动作携带的旧材料 ID 或参数，再经同一动作校验后提交。
`action_parameters.decision_recovery` 保存原动作、错误、修正次数和恢复原因。

确有未处理材料时不执行上述恢复；缺少候选、合法后续动作或配置来源时也不凭空编造工作。
本修复不改变答案验证或发布条件，不修改冻结实验 skill。

## 验证与使用

回归覆盖五种候选阶段、当前 schema 动作枚举、无事实不得设计，以及新材料仍可理解。
Main Agent、主循环和 Web 共 64 项测试通过。
这是代码与模拟状态回归；未取得用户失败运行的具体快照，未声称恢复了该次运行或完成端到端重跑。

重启后端使新代码生效。对已有失败任务，页面允许恢复时可以继续；否则新建任务。
