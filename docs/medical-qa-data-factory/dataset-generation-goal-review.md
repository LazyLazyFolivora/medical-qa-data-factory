# 面向 query-planner 的数据生成目标（待审核）

日期：2026-11-15  
状态：按用户指示作为改进依据；本文不代表现有系统已经达标。

实施优先级：当前先解决生成题目的能力与基本质量，不以日产量要求阻断本阶段；并行与效率优化后续再做。

## 1. 我们究竟要做什么

建设一个能自动、持续产出数据的系统，为 query-planner 训练检索动作选择能力提供题目与材料基础。

这里的 query-planner 是一个检索动作选择器：给定问题、已经获取的信息和可用工具，它需要选择下一步查什么、到哪里查，以及什么时候已有足够信息可以停止。我们希望它学到可泛化的检索方法，而不是记住某个实体的答案或固定工具顺序。

当前首先要解决的是：**从实体及检索到的材料中，稳定生成自然、有价值、适合检索规划的问题，并附上大体可靠的答案和可追溯出处，供人工审核。**

完整的动作选择训练数据，还需要比较检索路径的有效性与成本；仅生成问答对，并不意味着已经完成 query-planner 的训练数据集。

## 2. 什么问题适合 query-planner

题目应表达一个明确、有边界的信息需求，让检索者能够理解：

- 要查的对象和关系是什么。
- 目前还缺少哪类信息。
- 找到什么内容，就基本回答了问题。

读者只看题干，不会看到后台论文、检索笔记或出题理由。因此，决定问题含义的必要背景要写在题干里；专业机制细节不必提前全部塞进题干。

数据集要覆盖不同检索需求：既有少量查询就能回答的问题，也有需要寻找关联、连接多份材料、比较或补充信息的问题。不能只产简单属性题，也不能为了“难”而堆术语、子问题或无关检索步骤。

**题目复杂，不等于检索规划有价值；用过多个工具，也不等于这些工具都有必要。** 哪些动作有帮助，需要实际执行后判断。

不要求每道题都使用图谱、全文或多个来源。图谱可以帮助发现实体关系、扩展查询方向和定位文献，是检索索引的一部分；具体是否使用，由信息需求决定。

## 3. 我们希望怎样出题

基本方法是：**先找到内容，理解其中值得知道的事实或关系，再把它转成一个自然的信息需求。**

1. 围绕实体获取相关材料；需要时读论文正文。
2. 从已读内容中挑选有价值的事实、关系、解释、差异或发现，而不是只盯着数值和统计指标。
3. 思考一个没看过这篇论文的人，会怎样询问这件事，形成自然题干。
4. 根据材料给出简明答案，保留影响结论的适用条件和出处。
5. 先评价问题是否合适，再检查答案核心意思是否有据；明显错误修正或淘汰，其余保留给人工审核。

可以从单篇论文出题，也可以整合多篇论文。论文中的发现和结论当然可以成为题目内容；不要求每个结论都是教材常识或已被多篇研究重复验证。

从材料反向形成题目后，还要考虑：检索者不知道答案时，能否通过合理查询找到相关证据。不能只保存“知道答案以后才成立”的查询路径。

## 4. 题目的表达方式

优先用自然、直接的语言提出一个中心疑问。专业程度以表达信息需求所需为限：必要的实体、疾病、药物或机制名称可以保留，但不要把所有分子、结构域和缩写都放进题干。

允许简单事实、关系解释、比较和综合问题。专业术语不是禁词，通俗化也不是把问题改成没有边界的“为什么会这样”。

以下只展示表达方向，不是已经核验的题目或固定模板：

| 表达 | 判断方向 |
| --- | --- |
| 为什么癌细胞会耐药？ | 过于宽泛，不容易界定要查什么、何时查够。 |
| 肺癌对 EGFR 靶向药产生耐药后，MET 基因扩增可能起什么作用？ | 对象与关系较明确，具体机制可以放在答案中。是否有据仍需核对材料。 |
| 某试验中三个亚组的客观缓解率分别是多少？ | 通常更像报告中的指标摘录，不作为本项目的主要目标题型。 |

不能仅靠删除论文名和数字，就把某次实验结果包装成一般规律。也不能因结论来自单篇研究，就自动判定它不适合出题。应判断它是否形成了独立、有意义的信息需求，并保留必要的适用范围。

## 5. 质量标准：可用优先，允许不完美

目标是让一批生成内容中，**大约 80% 能达到基本可用、值得人工审核保留的程度**，而不是要求每道题、每个句子完美。

“基本可用”指：问题能看懂、值得问、适合检索，答案核心意思正确且有材料依据。措辞略生硬、解释不够细、非关键细节不完整，可以标注后交人工处理，不应因此反复重写或阻断整批产出。

明显的问题仍要处理，例如：

- 题干有错误前提，或者缺少导致含义改变的必要背景。
- 问题没有新增信息需求，答案只是重复题干。
- 答非所问，核心结论与材料相反，或者把推测写成确定事实并改变了主要含义。
- 把某个试验方案下的结果直接当成普遍结论。

模型评审和开发者评审都不是金标准。自动判断应保留理由和出处供人工复核，不能把评审模型的建议当成必须服从的事实。

不能靠不断拒绝、反复补证，只留下极少数题目来制造高合格率。要同时看合格比例、实际产量、重复程度和生成成本。

## 6. 每条数据应留下什么

当前出题阶段至少保留：

- 题干、候选答案、出处及关键证据。
- 来源实体，以及从材料到题目的形成记录。
- 实际检索动作、参数和返回内容；各步模型输入与输出。
- 自动评审结果、具体疑点和人工审核状态。

后续用于动作选择训练时，还需要形成：

- 选择动作前，检索者掌握的问题与已有信息。
- 可用动作、实际动作及其结果。
- 该动作补充了什么有用信息，以及耗时、调用等成本。
- 停止是否合理，是否存在更有效或更经济的路径。

生成系统执行过的路径只能作为候选轨迹，不能自动标成最优动作。出题时已知的答案和后台材料，也不能泄漏到模拟检索者尚未获取的信息中。

## 7. 当前阶段的验收方式

用真实模型、多个实体运行；每批完整保留成功、失败和未完成结果。由人工查看题目与答案，结合证据判断是否基本可用。

至少分别报告：生成和发布了多少题、问题本身是否合适、答案核心是否有据、是否重复、实际调用与时间成本。先评价问题，再评价答案，不因答案可从文献摘出就把坏题算成功。

约 80% 是工作目标，不是已经证明的稳定能力。小批结果只能说明该批表现；需要在不同实体和检索需求上复现。具体评估批量、人工标注规则及训练动作标签方案，后续再确定。

## 8. 批量生成与效率目标

系统必须支持持续、大批量生成。**在约定的模型服务与并发资源下，连续运行 24 小时，至少产出 1000 道可交给人工审核的完整题目。** 平均约每小时 42 道。这是系统总吞吐目标，不要求单个 agent 串行达到。

这里暂按“1000 道待人工审核的完整题目”理解，质量仍遵循约 80% 基本可用的目标，即预期约 800 道基本可用；不能把这两个数字混为一谈。若要求每天 1000 道基本可用题，则按 80% 比例估算，需要生成约 1250 道。具体统计口径待用户审核。

计数单位是有题干、答案及可追溯出处的独立题目。同一问题的修订版本、重复问法、不完整草稿和模型调用次数不计入 1000 道。自动生成完成与人工审核通过分别统计，人工审核耗时不计入自动生成吞吐。

并行是提高总吞吐的主要手段之一：

- 不同实体的探索与出题任务可以并行。
- 同一实体已有足够材料时，独立问题的答案生成和验证可以并行；共享已获取的材料，避免每道题重复下载和阅读。
- 保留必要依赖：问题判断通过后再验证答案，证据不足时再补检索；并行不意味着无视这些依赖。
- 并发数量应可配置，并按模型服务容量、限流和检索来源的承载能力调整。任务状态与产物应相互隔离，失败任务可单独恢复，不拖住整批。

并行不能替代单题效率改进。还应减少重复评审、无必要的补证及反复改写；避免少数难处理的题长期占用全部资源，让其他题继续产出。

验收需在实际部署条件下做连续运行，记录 24 小时完整题目数、去重后的基本可用比例、失败与恢复情况，以及模型调用、token、时间和资源成本。说明所用模型、服务容量及并发配置，不以短时峰值外推一天的产量，也不以无上限增加资源掩盖不可承受的成本。具体资源与成本上限后续确定。

## 9. 当前不追求什么

- 不追求完全消除模型幻觉，也不要求每道题自动审核到无可挑剔。
- 不以不断增加评审层、校验规则和重试次数代替出题能力改进。
- 不要求所有题目都困难、都涉及多篇论文或都经过图谱。
- 不把术语密度、答案长度或检索次数当作题目价值。
- 不把自动发布状态当成人工审核通过，也不把一次较好的批次当作整体目标完成。

## 10. 本次待审核的核心理解

我们要的是：**一个能从真实材料持续产出适合检索动作选择任务的问题、答案及过程记录的工具。题目自然且有边界，答案核心可靠，允许部分不合格，由人工完成最终筛选；在约定资源下，连续运行一天至少生成 1000 道完整题目。**

审核重点是上述目标是否准确，尤其是题目专业程度、query-planner 适配要求、“基本可用而非逐题完美”的质量尺度，以及每天 1000 道的产量口径。确认之后，再据此调整出题方法和执行流程。
