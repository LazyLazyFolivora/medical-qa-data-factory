# 页面使用的生产链路：自然问题与事实选择迁移

## 问题定位

页面“候选中”卡片在尚无最终 draft 时显示 question_intent。
原设计提示没有要求该字段是自然问句，因此直接显示了“查明……”“确定……并阐明……”的研究任务描述。
生产角色本来已通过 objective_skills.py 加载旧 skill，并非完全没有加载。
此前新增的实验 CLI 是另一条入口，冻结实验方法不会自动改变页面行为。

## 本次改动

- 事实理解：先读完整观察，再填写主语、关系、对象与条件，明确干预对象和效应背景，区分名称、分类与机制。
- 设计：新增按 claim 对齐原文的 claim_evidence_cards；新增 fact_selections 输出完整观察、第二事实、信息增量及 single/connected/insufficient 选择。
- 生产 skill 加载：不论难度，均加载 references/fact-selection.md。这是 fact-pair-v1 的生产契约适配，冻结副本不变。
- 候选文本：question_intent 明确为可直接展示的自然问句，不再是交给检索器的指令。
- 组合：同源不是拼接理由，名称含义不自动解释分类。原文 gene group 保留为基因群组，不混写蛋白家族或误译成基因组。
- 排序：不再因候选包含更多 claim 而自动加分。
- 兜底：移除由代码生成 “Ask about…” 意图的候选；高优先级事实无法形成支持充分的题时保留已有有效候选，不用模板硬造一题。
- 候选替换：修复批次已满时优先事实补设计无法进入的情况，只在模型实际给出可接受候选后替换末项。
- 写作：生产 realization 提示及示范使用自然问法、最小充分答案，不添加契约外的第二问；已有契约的语义仍保持不变。
- 追溯：fact_selections 保存为 question_design_notes，供检查选题过程；不作为事实依据传给验证或写作。

这是生产设计方法的适配，不是直接复用实验返回 schema，也没有把实验中的人工审阅冒充自动质量保证。

## 真实模型复测

使用 HGNC 的 RGS20 真实资料，通过生产 FactUnderstandingSubagent 提取事实，随后通过
ObjectiveQuestionDesignSubagent 生成候选；不是手工改写页面文字。

记录位于：

- data/experiments/rgs20-production-design-01：真实资料、提取事实和前两轮设计请求/响应。
- data/experiments/rgs20-production-design-02：同一份事实、明确分类概念后的两轮设计请求/响应。

第二组第一轮原始候选：

> RGS20 位于人类 8 号染色体的哪个区带？
>
> RGS20 属于哪个基因群组？

第二轮原始候选：

> RGS20 在人类中位于哪条染色体的哪个区带？
>
> RGS20 属于哪个已知的蛋白信号调控基因群组？

第二轮仍有不必要的修饰，不能宣称措辞已完全稳定。此次重点复测页面实际显示的候选设计；
没有运行独立答案验证和发布，也没有将这些测试题自动加入数据集。
第一组有“蛋白家族或基因组”的混译，保留原始记录，未将它当作成功样本。

## 使用

重启后端服务后，新任务会加载更新后的生产 skill 和代码。
历史已生成的候选及冻结契约不会被这次代码变更自动改写；检验新方法请新建任务。
不需要改用实验 CLI。实验冻结基线 fact-pair-v1 继续用于对照。

相关回归覆盖生产 skill 加载、自然问句提示、证据交接、设计说明保留、停止强制兜底、
题面语义、Main Agent、主循环和 Web。运行日志中的文本质量仍需结合原文判断。
