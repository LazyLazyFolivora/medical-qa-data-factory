# Persisted Radar diagnostics export

`python -m medical_qa_data_factory eval routes export-radar-diagnostics --views saved-view.json --scenario C --phase smoke --out diagnostics.jsonl` executes no model, retrieval or source import. It reads the exact saved view bytes and refuses to overwrite an output. The same diagnostic projection accompanies `import-radar`, including absent/invalid route traces.

The export retains structured error codes, rule IDs, source/record/version IDs, search terms and received page/cursor metadata, repair triggers, BioCheck issue text and sentence indices, and recorded numeric rejection reasons. It does not infer a cause when the host did not save one. Only named diagnostic containers and fields are traversed: full source bodies, questions, private prompts, raw model outputs, and numeric observation values are excluded. Diagnostic issue text may contain the short offending fragment needed to understand the issue; this is not a full-source export or an anonymization guarantee. The caller remains responsible for access control and secret scanning before distributing a bundle.

`scenario` and `phase` are optional labels from the frozen public execution manifest. They never come from private expected answers. Stage cost is reconciled from persisted call IDs and actual receipts. Duplicate IDs and missing usage are explicit, the complete token total stays null when uncertain, and only unique trustworthy calls contribute to the known lower bound. Conflicting duplicate calls contribute no trusted tokens and count as unknown in their affected stage (or `conflicting_stage` if stage assignment also differs). Each possible original stage is then marked incomplete, retains only its independent trustworthy lower bound, and lists ambiguous call IDs. Such stage ambiguity counts overlap; only the global unique-call ledger supplies experiment totals. Usage values must be finite nonnegative numbers; malformed nested payloads are never copied and make that call unknown. This is the analysis generation ledger; independent embedding, rerank and indexing services need separate ledgers.

Export success is not route integrity, BioCheck PASS, business validity or an independent scientific judgment. Native report state remains unchanged. Missing diagnostics stay missing rather than being reconstructed from the question, source text or private grading material.

## Claim-level native report diagnostics (section17.2)

The existing white-list now traverses native `report.verify` / `report.verification`
paragraph `units[].claims[]`, selected `evidence` / `support`, support-audit checks,
verification errors and completion metadata. It preserves native unit/claim IDs,
claim indices, verdicts, issue labels, sentence numbers and evidence/version/segment
references plus Unicode locator offsets. It never exports `quote`, `span`, `text`,
`draft`, `context`, `source_context`, `raw_response` or nested arbitrary payloads.
A verdict/quote error is passed through, not recomputed. Existing allowed diagnostic
reasons can contain a short offending fragment; the exporter is not a redactor.

`diagnostic_presence` describes whether the report, verification and claim checks
were actually present. `missing_diagnostic_fields` names missing native identity /
verdict fields on existing checks; no claim ID is synthesized from a list index,
and absent checks do not become NOT_RUN/PASS. Model call accounting is unchanged:
new report rounds use their actual distinct call IDs, prepared / receipt-not-sent
reservations are excluded from sent cost, and failed sent calls without usage stay
unknown. The existing B2 nine-call /238,472-token source-free ledger was replayed
without any token, stage or issue changes.

`tests/fixtures/biocheck_native_diagnostics.json` was generated by the actual
BioCheck `core.verify(mode="paragraph")` and `core.audit_support` at revision
`b88da7bc3b4614e4537d340a9deade10c1c3980c`, using only local synthetic callback
outputs. It is a shape/regression fixture, not an experiment or scientific score.
The confirmed native metadata paths are `AnalysisView.result.assessment_axes`
and top-level `AnalysisView.human_review_context`. The exporter projects these
as distinct sections, without recomputing any grade, binding or review status.
Missing native objects remain null with presence `absent`; missing required
metadata is named in `missing_diagnostic_fields`, never filled with F/6 or an
approval. Multiple source / information assessments retain their array order
and cardinality. Native unassessed null actor/time values remain null.

Only declared assessment scalars and exact ProviderRef fields are retained.
Claim text, free-text assessment/confirmation basis, arbitrary payload/source
objects and human review text/conditions are excluded. Native heat is open JSON;
only its existing `score`/`qualification` metadata is projected, rather than
copying arbitrary nested content. Human-review output keeps the actual native
reviewer/time/revision, target type/IDs/hashes, basis references, scope, decision
and binding status. `accepted_within_scope` is not converted to alert approval.
A changed or different target retains that native binding status. No separate
entries/kwargs path exists to reconstruct a review in the factory.

native `reason_code` and `changed_binding_fields`; missing codes/reasons stay
missing and are never inferred from text or from a nearby changed claim.
