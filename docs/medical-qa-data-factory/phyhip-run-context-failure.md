任务：`web-d3c88513-224d-4921-bb1e-536bfe5c9a5d`。
检查时快照修订号 200，状态 CLAIMS_PROPOSED，stop_reason 为空。

## 实际发生了什么

- 累计 28 个 design_questions 决策，其中 27 个有上下文超限失败记录。
- 曾经生成 3 个候选，目前全部为 INDETERMINATE，未发布。
- 同时还有 10 个验证失败、2 个检索失败记录；本次处理后续设计重复失败的直接原因。
- 模型服务上限为 32,768 token，错误说明输入至少 32,769 token，返回 HTTP 400。

设计输入将原文重复包含在逐事实卡片、分组和摘录中；一次来源被多条事实引用时反复复制。
服务端上下文错误经过适配器有限重试后，仍标记为可重试；主循环记录失败后继续选择设计，形成空转。
此前新增的逐事实完整原文卡片加剧了输入重复，本次修正该交接方式。

## 修复内容

候选事实提供一次，原始锚点引文提供一次，claim_evidence_cards 仅记录 claim_id 与 source_anchor_ids。
分组只保留组、材料、事实及锚点 ID，不再重复嵌入事实和原文。完整引文保留，不通过切掉条件来压缩。

模型适配器在有限压缩重试仍超限后，将错误标记为不可原样重试；主循环保存失败并进入 RECOVERY_REQUIRED，
保留恢复前状态，不继续重发相同阶段。不将该错误伪装成“资料不足”或成功设计。
