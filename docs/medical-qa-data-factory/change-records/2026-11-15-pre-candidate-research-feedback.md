# 出题前补证误用候选 ID

## 真实问题

`cftr-20261115-074412` 从实体启动，目标3题、24个外层动作。模型最初希望研究不同 CFTR 突变的功能缺陷与调节剂机制，却在第3至6步把 discovery opportunity ID 当作 hypothesis_id，连续调用全文工具失败。后续研究委托也混用了 ID。最后发布一道调节剂分类题，并提出两道题干相同的治疗覆盖范围题，停在动作上限；这不是稳定生成综合问题的成功。

全文工具本来允许出题前使用 discovery 模式。原错误只提示 verification 需要已有 hypothesis_id，模型理解成“补上 ID”，反复提供并不存在的候选。研究工具也只有同样简短的错误。

## 修改

仅修改 `react_main_agent.py` 两条前置条件错误反馈，保留原检查和执行逻辑：

- 全文读取：明确 opportunity/research ID 不是候选 ID；出题前用 purpose=discovery，省略 hypothesis_id，保留材料 ID 和 evidence_need。
- 研究委托：明确任务 ID、opportunity/research ID 不是候选 ID；出题前省略 hypothesis_id，保留调查需求、提供方偏好和材料 ID。
- 两者都说明本次尚未执行工具，已有候选验证才使用 hypotheses 中的实际 ID。

代码评审确认说明与执行一致，无门禁或状态变化。

## 验证边界

第一次重放 `cftr-20261115-074827` 只包含全文工具反馈修正，模型转而调用研究工具并连续4次填错 ID，因此暴露了第二个入口的问题。

第二次重放 `cftr-20261115-075024` 已包含两个入口的修正，但模型直接选择出分类题，没有触发新反馈，不能用它证明反馈有效。已结束4个动作。

定向对照 `research-feedback-replay-20261115` 将第一次研究工具失败的真实快照中旧反馈替换为当前验证器实际生成的反馈，注明修改范围并重算派生材料摘要；原始快照保持不变。随后只调用一次真实主模型，不执行研究工具。模型正确省略 hypothesis_id，保留原调查需求和 PubMed 偏好，返回通过验证的 research_evidence。这证明该案例的反馈能够纠正参数，不证明全文获取或新题已完成。初次准备该对照时因派生材料 digest 未更新而本地失败，未调用模型；修正派生快照后才进行上述真实调用。

`cftr-20261115-075146` 从原完整运行的第24步继续，已结束12个动作。确实取得并阅读 PMID18292812 正文；另两篇正文未取得。模型探索新的修饰因素方向时却绑定了旧的药物覆盖题 ID，说明有效 ID 也可能语义关联错误。最终又出现“材料如何解释……”和“一项研究将……解剖为两个主要组件”的题干，仍不符合目标，不能以正文取得或已有发布数量代表成功。所有实验使用隔离存储，保留原任务数据，没有清库或重启正式后端。

该轮结束后修改主 agent skill 原有的委托说明：新方向/discovery 机会不传 hypothesis_id，核验已有题才传，并先核对实际题干与本次调查是否对应。没有增加语义门禁；此项新说明尚待真实链路验证。

另记录主 agent 输入膨胀：续跑一轮的 payload 约273198字符，其中 latest_observations 151915、prior_searches 39977、research_history 22571，当前 hypotheses 约996字符。模型曾混淆候选对应内容和状态。上述统计只表明值得做上下文对照，尚不能证明长上下文是误判的原因。正式上下文上限、模型与压缩配置未改变。

## 提前压缩的单步实验

`cftr-controller-compact-20261115` 使用同一续跑任务 step-05-before 状态，仅在实验进程中将 compact_trigger_ratio/compact_target_ratio 调为0.25/0.20；同时使用上述主 skill 委托说明，因此是组合干预，不能单独归因于压缩。首次配置只改触发比例导致比例约束失败，未调用模型；随后同时设置相容的目标比例。

既有摘要机制调用3次（各自输入31113、20873、9696 tokens），最终主 agent 输入31343 tokens。它选择发布已有验证提案的候选，动作通过当前门禁，未再绑定旧候选调查新方向。但公开 rationale 仍混淆旧版本关系，不能宣称状态判断完全正确。本实验只生成一个动作，没有实际执行发布，也没有生成新题。下一步应在隔离完整流程中比较状态追踪和题目质量，再决定是否改变正式压缩策略。

另外确认 PubMed 新查询指导确实进入了真实请求：首次选用尚未加载指导的 PubMed 被程序拦下，加载后才重新生成参数。首条查询仍堆叠多个概念，说明不能把模型没有遵循指导误诊为 skill 未加载。
