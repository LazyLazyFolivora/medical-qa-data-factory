# 问题先行：原文交接、旧题评审与范围外推

本记录接续 `2026-11-13-question-first-pipeline.md`。目标仍是独立成立的领域知识问题，先审问题，再验证答案。以下均为隔离目录中的真实模型运行，未写生产题库。模型判断不是金标准，PUBLISHED 也不自动代表人工认可。

## 已定位并修复的问题

### 作答者看见的原文，验证者未必看见

`egfr-20261113-194639` 选中了两段各 6,000 字符的原文。盲答初始每段只见 1,000 字符，再各打开 1,000 字符，实际只读到 12,000 字符中的 4,000。它提前作答后遗漏机制，流程把信息交接问题误当成题目问题。

`EvidenceView.initial` / `generate_with_evidence` 增加可选 `verbatim_text_budget`。既有证据验证在原始文本总量不超过共享 32,000 字符预算时直接交付；结构化 JSON 仍按字段导航，大材料仍可按引用打开。默认行为保持不变，不无限扩大上下文。

同一题和同一材料回放 `egfr-20261113-200107`，实际请求完整包含两段原文，两个主动作完成验证和发布。这是该交接缺陷的直接对照证据，不是所有机制题都已解决。

### 旧候选绕过问题先行

`cftr-20261113-200203` 复用了旧的“接近正常”问题，旧流程竟允许发布。原文仅支持改善，不能支持接近正常，此例明确不计成功。

现在 `verify_answer` 和 `publish_question` 要求当前问句已有当前版本的 question reader 审批。新发现的问题使用 discovery 审批；旧题、改写题由 `review_candidate` 先做不含候选答案的 reader 判断。拒绝时保存 REWRITE 和具体原因，不先跑答案验证。

`cftr-20261113-200751` 实际阻止旧坏题，形成“G551D和F508del两种CFTR突变在蛋白质定位和缺陷机制上有何不同？”；`cftr-20261113-201454` 完成该新题验证与发布，旧坏题未发布。`agent_loop` 同时将 `candidate_usability_review` 的 reader/reviews 反馈交给修订，避免改题者看不到拒绝理由。

共享实现位于 `generation/question_reader.py`，discovery 和候选复审共用。审批版本含 reader 模板 hash；修改评审指令后，旧审批不再静默沿用。当前生产流程只有一次基于原文、不看候选答案的 reader。

### 排版被当成答案数量

CFTR 盲答曾返回一个完整解释，又把同一解释分成两条总结，导致 EXACTLY_ONE 被误判。现在指令明确：一个解释的互补环节组成一份回答，不重复分条；多个条目用于问题真正要求的不同实体或选项。没有删除答案基数检查。非穷尽举例与 EXACT_SET 的语义也已区分。

## 没有保留的实验

尝试在原文 reader 前增加一个只看题目的 scope reader。两次 TNF 对照均未稳定识别“同一自身免疫疾病”等措辞，未显示额外调用的收益，因此移除生产中的额外阶段，不以不断叠加评审解决单个样例。实验提示词和请求响应保存在 `reader-two-views-v3`，不把该实验版本当作当前生产代码。

所有实验目录位于 `data/experiments/question-first-lab`，保存逐步 before/after、原文、debug_trace 和 prompt-and-output.md。实验从 checkpoint 恢复时，会在新目录复制已有状态；原始失败记录保留。

## 最新评审被误读为较早的通过

`tnf-20261113-204156` 的 sequence 128 保存的是 REWRITE（避免把两类模型笼统称为自身免疫疾病模型），reader 本身是 ACCEPT。主 agent 却说“最新评审 KEEP”，忽略了候选评审的具体结论。发布门禁正确拒绝，但模型通过重复评审得到 KEEP 后发布，不能视为完成了修题。

现在主输入的 `candidate_reviews` 直接列出每个候选最新的完整意见；与门禁共用 `latest_candidate_review`，按实际 sequence 选择。已有非 KEEP 时不执行答案验证，发布反馈直接指出最新意见及原因，而不是一律提示再跑评审。模型仍负责决定如何修题或补证。没有增加新的模型评审调用。

共享 reader、审批 hash、范围提示和最新评审交接已完成代码审查；未发现新增回归。真实流程回放另行保留，静态审查不替代模型运行结论。

`accepted-examples.json` 增加 `cftr-20261113-201454` 的最终发布稿，逐句核对两份原文：G551D 正常膜定位而门控失效；F508del 加工/ERAD 缺陷、膜递送减少及救援后稳定性/门控异常。当前保留四例，不包含 APOE 的范围外推反例或 TNF 的重复评审放行例。

- `react_tools` 为候选复审加入 `previous_review`。此前 skill 要求检查旧反馈，但调用没有传。现在复审者需说明缺陷是否实际解决，推翻旧意见要给原文依据；评审调用不会应用建议题干。
- `tnf-20261113-205322`：接到旧反馈后仍曾由 REWRITE 转 KEEP，理由是原题所列 EAE/结肠炎已经足够限定。分类措辞在这里有模型判断分歧，不将所有翻转一概认定错误。

## 字段生成顺序与检索精度

进一步对照 `main-projection-20261113-211341`：输入内容不变，只将输出schema的简短 rationale 排在 action 前。压缩和原输入两种情况下分别选择 design_questions、discover_questions，均继续处理第二题，未错误停止。这是小样本证据，不能声称保证决策正确。生产 `ReactChoice` 只调整字段顺序，不增加调用，不要求长篇推理，不改变动作和参数契约；后续完整回放检查实际效果。

`brca1-20261113-210512` 虽发布2题，第二题却转到ERBB2。检查实际检索发现：模型请求 `symbol=BRCA1`，适配器转换为 `[All Fields]`，得到EGFR、ERBB2等广泛命中；CFTR任务也有类似噪声。不是模型提交了这些无关基因作为初始查询。现将显式symbol改为 `[Gene Name]`，名称/mention用 `[Gene/Protein Name]`，数字GeneID仍用uid查询。同步更新NCBI查询skill，仍由模型核对返回身份。

依据：[NCBI Gene官方字段定义](https://www.ncbi.nlm.nih.gov/books/NBK3841/table/EntrezGene.T.fields_used_to_categorize_i/?report=objectonly)，Gene Name包括规范符号、别名和locus tag。真实只读API查询：BRCA1 `[Gene Name]` 返回1条GeneID672；CFTR返回1条GeneID1080。没有静默回退到广泛命中。完整真实任务继续观察修复后源头噪声和实体方向是否改善。
