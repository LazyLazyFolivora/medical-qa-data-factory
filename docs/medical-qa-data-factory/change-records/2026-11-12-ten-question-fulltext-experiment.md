# 将目标提高到10题是否促使模型读取正文

## 实验条件

BRCA1，当前默认Qwen131072，free策略，difficulty仍为CLI默认easy；来源PrimeKG、PubMed。
与 brca1-fulltext-choice-20261112 相比，目标从1提高到10，动作预算从22提高到100，模型调用上限从80提高到240。未修改代码、prompt、skill或模型配置。
这是一轮新的实时运行，不是固定检索结果和随机性的严格配对实验；数量及预算同时变化，不能据此得出统计因果结论。

工作目录 data/experiments/brca1-ten-questions-20261112。experiment.json保存参数和相关文件哈希；debug_trace保存每次请求响应及工具结果；inspection.json保存最终候选状态、评审和错误核对；release保存导出结果。

## 实际结果

| 项目 | 数量 |
|---|---:|
| 总动作（含stop） | 34 |
| 检索 | 2（PrimeKG一次，PubMed一次） |
| read_artifacts | 2 |
| read_source_details | 0 |
| fetch_full_text=true | 0 |
| synthesize_evidence | 0 |
| design_questions | 5 |
| 候选记录（含修订版本） | 7 |
| review_candidate | 5 |
| verify_answer | 7 |
| tool_feedback | 10（其中9次发布未执行） |
| 发布 | 1 / 10 |

目标提高后，模型在第一题发布后继续设计候选，但没有追加检索，也没有获取正文。动作主要消耗在同批摘要的出题、验证、改题和失败发布上。

唯一发布题：利用饱和基因组编辑技术对BRCA1关键功能外显子进行的单核苷酸变异功能筛查中，鉴定出的无功能错义变异和破坏表达的变异数量级分别是多少？
该题仍偏具体研究数字摘录，自动发布不能当作已经满足自然查询题目标的人工确认。

## 停止原因核对

模型在34/100步主动stop，声称宿主状态导致持续的评审/提案不匹配，工具范围内无法修复。记录不支持“没有可恢复路径”的判断：

- hypothesis.5adc... 和 hypothesis.d581... 有验证提案，但没有候选评审；缺的是对各自ID调用 review_candidate。
- hypothesis.4d7... 有验证提案，但最近候选评审是 REWRITE，指出公开题干缺一线治疗条件；需要根据意见修订或处理，不能直接发布。
- PARP候选没有验证通过提案，前面已有明确的答案修订反馈。

程序拒绝这些发布符合现有前置条件。此处首先是模型未按具体缺口选择下一工具、重复调用发布，并将局部失败误判为整个任务无法继续。不能仅凭模型停止理由断言状态库损坏。

## 结论

本轮未支持“将目标改成10题就会读正文”的猜测，但也不是证明任何实体/任何运行都不会如此。更大的数量目标带来了更多候选处理，没有自然转成更深的文献阅读；实验在候选处理/恢复环节提前结束，尚未观察到摘要方向真正耗尽后模型的行为。
下一步应分别检验候选缺口的恢复决策，以及在明确存在方法/结果缺口时的正文选择。不能继续只靠增加目标数量推断正文工具的使用倾向。
