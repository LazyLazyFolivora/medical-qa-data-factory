# 候选工具按当前状态提供

## 实际问题

APOE `apoe-20261115-034910` 中，主模型承认最新评审为 REWRITE，仍选择发布。TP53 多次选择对未改变输入重新评审。单纯增加解释没有阻止这些动作。

## 修改

- 提取 `candidate_review_inputs.py`，评审执行和主控制器复用同一套输入及 hash。
- 每轮构造可用动作 schema：只有满足已有发布前提的候选才能选择发布；同一输入已有评审结果时，不再提供该候选的重复评审。
- schema 中的候选 ID 枚举与运行时校验使用同一份目标列表。修订、补证等动作仍由模型选择。
- 不改变题目正确性标准，不把状态约束当成质量判断。

## 检查与观察

代码审查无阻断问题。导入及真实 APOE 保存状态检查通过：四个已评审候选的 hash 与历史值一致；没有合法发布或重复评审目标，相关动作从 schema 中移除。

真实续跑 `tp53-20261115-035625` 使用默认模型配置，从 `tp53-20261115-033811/after.json` 开始。前两步为验证与发布，未出现非法发布，但不能据此宣称质量改善：验证器仍接受了此前指出的机制归属问题。该实验采用隔离存储，不是生产发布。

同时发现两条独立问题：

1. 本次历史压缩把 Class II 特异的机制证据缺口写成 resolved，摘要可能把待核实假设提升为结论。需要追查其输入及状态覆盖，不能把摘要当证据。
2. 旧 APOE 续跑在再次保存 `material.pubmed.40496670` 时发生 IdempotencyConflictError。保存了失败现场，尚未确定是同源内容变化还是元数据冲突，不能直接覆盖旧材料。

本记录不代表目标完成。还需检查后续实际产出，修复上述问题并进行新实体验证。
