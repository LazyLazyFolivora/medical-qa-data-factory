# 去掉新 ReAct 路径中的隐式业务判断

## 问题

真实试跑与代码复查显示：外层虽由 LLM 决策，检索内部仍自动多轮查询、无选择时按词频补选材料；PubMed 底层空结果自动截短查询；出题还按答案和事实重叠删题、排序及自动修复。这些行为削弱了主 Agent 的实际控制权。

## 改动

- 新 ReAct 检索一次只执行一个模型指定的查询，跳过内部 SearchRoundDecision 模型及其多轮逻辑。返回原始材料并标记 unreviewed，不声称材料已被选中或足够。
- 主 LLM 通过 read_artifacts 和 understand_facts 的材料 ID 选择阅读和使用哪些材料；不相关材料可以留在索引中不用。模型决定下一次搜索。
- PubMed 不再自动缩短查询。嵌套字典误作 symbol/term 的请求返回参数错误，不再转成字符串搜索。
- 默认不自动追加全文抓取。主 LLM 可在 PubMed 检索参数中显式指定 fetch_full_text=true；全文抓取失败作为 detail_trace 观察返回。
- 新出题路径保留设计 LLM 返回的顺序，不按相同答案、80% 事实重叠、启发式优先级或未命中优先事实自动删除/替换候选；去掉自动 portfolio 修复。已有候选和目标仍提供给模型，由模型判断重复和是否修订。
- 完全相同的持久化候选仍幂等去重；未知引用、参数类型、状态一致性、发布上限及已完成的 LLM 评审/验证前置条件仍由程序检查。
- skill 明确要求阅读实际生成题干，不能把改写计划当作已完成结果；澄清自包含、独立检索和证据解释。

## 边界

Web/CLI 的新 ReAct 决策使用以上路径；旧协议检索/出题逻辑仍保留供兼容使用。盲答、证据复核、难度评估仍为专用 LLM 调用组成的固定检查工具：判断内容由 LLM 给出，宿主不因此自动决定补查、修订、拒绝或发布。上下文超限的技术性拆批仍保留。
