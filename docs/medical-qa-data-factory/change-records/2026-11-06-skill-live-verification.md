## 观察到的链路

1. 前三次材料引用抄错，返回 Unknown artifact；第四次进入事实理解。
2. 第一次出题仍围绕 BRCA1 与 AML 亚型做关联列表，产生两题。主 Agent 指令把若干关联名称视为非显然集合，没有建立必要查询依赖。
3. 评审发现集合完整性风险，却建议把题干改成“PrimeKG 数据库中有哪些”。还用“外部检索违背证据自足”作理由，与新 skill 的定义冲突。
4. 后续又生成两题：重复的无界关联枚举，以及从题干给定疾病列表挑细胞遗传/分子特征的分类题。仅凭名称辨认可能形成明显捷径，不能标为可靠困难题。
5. 六次评审中 KEEP 2 次、REWRITE 3 次、REJECT 1 次，分别是评审调用次数，不是六个不同候选。没有成功执行 verify_answer；证据引用归属和缺少独立材料等前置条件阻止其进入答案验证。
6. 一次补证 PrimeKG 请求只给 native_id 而没有 mention，适配器返回查询校验错误。主 Agent 又去读发现阶段材料，未建立有效独立验证证据。
7. 最后一次设计明确返回不足：单条关联不能支持完整集合与交叉筛选。这是局部正向信号，但前面的无效题目与评审漂移仍存在。

## 本次结论

这次修改不能算质量问题已解决。skill 明确写出的原则仍被部分调用忽略或误解；增加说明并未使模型稳定按原则执行。主要需分别定位：主 Agent 设计指令是否把子模型带回错误方向；出题模型是否读懂材料不足；评审是否真的区分自包含与无需检索。与此同时，11 次工具参数反馈显示引用协议可用性是独立瓶颈。

下一轮应先用本次具体失败输入做小型真实回放，定位哪段输入或指令导致错误，再只改该点并完整复测；不继续盲目堆叠 skill 文本。长 ID 可改为稳定短引用，底层恢复原 ID，避免模型抄写哈希，这不替模型做业务判断。
