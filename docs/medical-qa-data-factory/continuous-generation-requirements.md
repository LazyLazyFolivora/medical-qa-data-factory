# 持续自动出题需求

日期为 2026-11-05。状态为待实现。本文件定义前后端交付要求，实施设计参考 [批量并发出题设计](batch-dataset-generation.md)。

### 2026-11-05 首版实施进度

已接通自动遍历 PrimeKG、持久化实体账本、1–4 个 worker、暂停恢复、同版本实体去重，以及三个页面。

- `/production` 配置目标题数、难度、单实体题数、并发数、实体处理上限和动作预算，实时查看进度。
- `/publication-runs` 按触发 ID 展开已发布题目；历史单实体运行按原 run ID 分组。
- `/published` 查询全部已发布题目，支持分页、题干搜索和实际难度筛选。

运行使用工作目录内的 `production.sqlite` 保存账本；`production-owner.sqlite` 防止多个进程同时调度。重启后通过页面恢复。模型调用和每个数据源调用分别限制并发为 1，实体之间可以交错执行不同阶段。首次读取实体目录可能触发索引构建。

单个实体执行异常会记录错误并继续其他实体；连续三个实体执行异常会暂停生产，恢复时重试失败实体。当前版本继续复用单实体内部的检索失败处理，按错误类别自动退避、全局费用预算、跨实体语义去重和固定快照导出仍按后续需求实现。已有源调用失败被单实体流程判为正常完成的情况，需要在单实体故障策略中继续完善。

自动化测试覆盖并发、暂停恢复、重启恢复、跨触发去重及真实单实体链路的模拟模型联调。实际模型下的持续生产质量和长时间稳定性仍需运行验收。

## 1. 产品目标

用户配置实体来源和出题要求后启动生产。系统自动遍历尚未处理的实体，通过多个 worker 并发执行现有单实体出题流程，保存处理进度和合格题目。用户能够随时查看、暂停、恢复和导出。

生产目标是形成符合 query-planner 要求的数据集。题目须客观正确、题干自足、具有实际检索价值，难度按解题所需的检索决策评定。已发布题目与隐藏答案、证据分别管理，保持现有题目质量要求。

用户无需逐个选择实体，也无需预先上传实体列表。实体处理记录跨服务重启、运行会话和导出操作保留。

## 2. 使用流程

1. 用户进入持续生产页面，选择数据源、实体类型范围、难度和单实体题数上限。
2. 配置 worker 并发数与生产预算，确认后启动。
3. 系统领取尚未处理的实体，并行出题；每个实体完成后自动处理下一个。
4. 用户查看整体进度、活动实体、题目产出和失败原因，点击实体可进入现有运行详情。
5. 用户暂停时系统停止领取新实体，活动任务保存断点后暂停。
6. 恢复时继续原任务，跳过已完成实体。
7. 用户筛选并导出已发布题目，导出记录固定数据集内容与版本。

## 3. 后端功能需求

### 3.1 自动遍历与实体处理账本

第一版接入现有 PrimeKG 实体来源，支持按实体类型筛选。遍历需要分页，避免一次把全部实体和关系加载到内存。实体筛选和读取应使用适合实体查询的索引或实体目录。

账本以来源、实体类型、稳定 ID 和处理版本识别任务。保存实体名称、run_id、状态、领取者、断点、尝试次数、产出数、时间和结束原因。跨来源实体合并须有身份映射依据。

已完成且零产出的实体默认跳过。临时失败进入待重试状态。永久失败保留诊断，用户可在修复后显式重试。创建新会话、刷新页面和导出数据均不能重置账本。

模型、skill 或数据源版本变更须记录。默认沿用已有处理进度；重新处理已完成实体需要显式创建新的处理版本，保留历史结果。

### 3.2 并发调度

提供可配置的固定 worker 线程池，建议首版默认并发数为 2。单个 worker 同时执行一个实体。同一实体任务只能由一个有效执行者提交结果。

领取、续租和释放必须持久化。进程异常退出后能够识别遗留任务，并在确保旧执行者不能继续提交的条件下恢复。线程锁之外还需要领取事务、执行身份校验和幂等提交。

每个实体使用独立上下文与运行目录。数据库连接按线程隔离，客户端共享须满足线程安全要求。模型调用并发、数据源请求速率和实体 worker 数分别限制。现有单实体入口与持续生产共用资源限额和任务领取规则。

### 3.3 单实体出题

复用当前实体检索、事实理解、题目设计、独立验证和发布流程。已完成候选未达到目标时，继续探索未查过的方向，受实际预算限制。

单实体外层探索上限沿用题数上限乘以 3 再乘以难度系数，简单为 1、中等为 2、困难为 4，多难度取最高系数。候选补证使用独立上限。

中等目标允许保留合格简单题，简单题不计入中等配额。记录总发布数和计入目标数。资料不足时允许零产出，必须记录具体结束原因。

### 3.4 暂停、恢复与结束

生产任务支持待启动、运行中、正在暂停、已暂停、已结束和需要处理的故障状态。实体任务支持待处理、运行中、等待重试、已暂停、已完成和失败状态。

暂停先停止领取，再让活动任务在安全边界保存断点。长时间工具调用需有超时。页面显示暂停中的活动任务数，全部保存后才显示已暂停。恢复沿用原 run_id 和断点。

关闭页面不影响后台生产。服务重启后加载账本，界面展示可恢复任务。第一版建议重启后等待显式恢复，避免服务启动即意外发起大量模型请求。

达到配置的生产预算或产出目标时停止领取新实体。已在运行的任务应安全收尾或暂停。实体范围遍历完毕时显示来源耗尽，区分是否仍有待重试实体。再次扫描来源时跳过已有记录，只处理新增或明确要求重跑的实体。

### 3.5 错误与重试

保留每次请求的数据源、查询参数、时间、耗时、错误类别、具体异常，以及可获得的 HTTP 状态和超时信息。保存时遮蔽凭据。

网络超时、限流和临时服务错误采用有上限的退避重试。错误参数带具体反馈修正。配置缺失、身份解析异常和数据源损坏提供可操作的诊断。持续同源故障应减少或暂停相关请求，其他可运行任务继续。

失败请求消耗真实调用成本和失败重试额度，但不能证明某方向没有可用信息。不得因服务故障把实体标记为正常探索完成。错误详情从工具到 API 再到前端必须保留，旧记录缺少详情时明确说明。

### 3.6 预算与统计

支持配置并发数、单实体题数目标、难度目标，以及有限的生产调用或成本预算。具体额度字段遵循已有运行预算契约。无可靠费用信息时显示未知，不能当作零成本。

统计已扫描、待处理、运行中、等待重试、暂停、完成和失败实体数；统计已发布题数、计入目标数、实际难度分布、候选状态与资源消耗。明确统计所属生产任务和处理版本，避免重复累计恢复前后的记录。

来源总数未知时显示已处理数量和当前进度，不虚构百分比。并发调用前预留预算，结算实际用量，防止多个 worker 同时超额领取。

### 3.7 数据集汇总与导出

统一汇总已发布题目，保留实体、运行、证据、评审和配置版本的可追溯关系。跨实体产生的重复问题需识别并标记，正式导出按明确的去重策略选取。

支持按实体类型、实际难度、生产任务及时间筛选导出。导出使用固定快照，记录题目集合、过滤条件、格式版本和生成时间；运行期间新增题目不能改变已生成的导出包。

planner 可见内容与隐藏答案、证据、评估资料分离。字段映射及工具环境与 query-planner 联调确定，参见 [跨项目验收标准](../query-planner-training-data-acceptance-criteria.md)。生成器内部检索轨迹仅作为审计资料；planner 训练轨迹由下游实际求解产生。

## 4. 前端功能需求

| 页面或区域 | 必须提供的能力 |
|---|---|
| 持续生产配置 | 选择实体来源与类型、难度、单实体题数、并发数和预算；展示配置校验错误 |
| 生产控制台 | 启动、暂停、恢复；展示运行状态和暂停中的任务；刷新后恢复展示 |
| 总体进度 | 实体状态计数、已发布量与目标计数、难度分布、资源消耗和结束原因 |
| 活动 worker | 当前实体、当前阶段、最后进度时间和关联运行入口 |
| 实体处理列表 | 搜索实体，按状态筛选并分页；查看零产出、失败和重试记录 |
| 失败详情 | 数据源、具体查询、异常消息、发生时间、重试次数、下次重试时间；支持修复后重试 |
| 题目列表 | 查看已发布问题、答案、难度和证据入口，标记附加简单题与疑似重复 |
| 导出管理 | 筛选导出范围、查看数量、导出状态、下载结果和 manifest |

复用已有单任务详情、候选题和证据页面。控制操作在请求期间防止重复点击，失败后显示具体原因。启动或恢复的重复请求不得创建重复执行任务。

使用增量或轻量轮询更新概览，详情按需加载。列表必须分页，后台生成时页面和暂停操作仍可响应。状态展示区分故障、证据不足、预算耗尽和来源遍历完成。

## 5. 接口与数据契约

需要提供配置读取与校验、创建生产任务、任务列表、任务详情、暂停、恢复、实体分页查询、失败重试、题目查询、创建导出及查询导出状态等接口。

创建、恢复和重试接口必须具有幂等语义，返回稳定任务标识和当前状态。异步工作提交后及时返回，由查询接口提供进度。参数非法、状态冲突、数据源不可用等错误返回稳定错误码及可读详情。

生产任务关联多个实体任务，每个实体任务关联一个可恢复的单实体 run。处理记录跨生产会话去重。导出包独立关联固定题目集合。具体路由和 schema 在实现时遵循现有项目契约，不能把原始错误直接拼入不可解析的文本响应。

## 6. 验收要求

| 场景 | 通过条件 |
|---|---|
| 自动循环 | 无需输入实体列表，系统自动处理完一个实体后领取下一个 |
| 多线程 | 至少两个不同实体实际并行，任务内容和上下文没有串用 |
| 去重领取 | 并发领取或重复启动不会同时处理同一实体的同一版本 |
| 零产出 | 正常探索结束但零产出的实体记账，后续默认跳过 |
| 暂停恢复 | 暂停停止新增领取，活动任务保存断点，恢复后继续原 run |
| 重启恢复 | 服务重启后账本和结果完整，已完成实体不会重新生成 |
| 故障恢复 | 注入超时、限流和参数错误后能查看具体原因，并执行对应重试策略 |
| 故障隔离 | 一个实体失败不会阻塞所有健康任务，同源持续故障不会导致请求风暴 |
| 预算控制 | 并发情况下仍遵守预算，停止原因可解释，恢复不会重置已用额度 |
| 数据集导出 | 题目集合固定，重复发布不会重复导出，公开与隐藏资料隔离 |
| planner 联调 | 样本能被下游读取和实际求解，工具可访问性、证据和难度评估可复核 |

首轮试运行建议自动处理 10 个实体，人工抽查题干、答案、证据和检索价值。先验收暂停恢复及两个 worker 的隔离，再提高生产规模。具体质量阈值按跨项目验收规范执行。

## 7. 实施拆分

第一阶段完成后端持久化账本、自动遍历和单 worker 执行，前端提供配置、启动和实体进度。

第二阶段完成暂停恢复、失败重试与详细诊断，并接通前端操作和断点展示。

第三阶段完成多线程领取、连接隔离和全局限流，前端展示 worker 状态与并发资源消耗。

第四阶段完成跨实体去重、固定快照导出和 query-planner 联调，形成可重复验收的小规模数据集。

首版采用线程池。若以后执行模型生成代码，需要另行设计执行沙箱；多机 worker 和按覆盖缺口自动选择实体作为后续扩展。
