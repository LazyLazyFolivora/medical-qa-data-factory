# 研究 agent 的持续阅读摘要

## 问题

阅读原文已保存，但研究上下文主要包含材料卡片、最近三次工具结果和上一轮模型笔记。模型把 findings 为空理解成没有读好，连续重读同一份 EGFR NCBI 记录。

## 修改

- ResearchSession.reading_memory 从实际阅读工具输出提取材料和已返回段落，合并重复内容。
- 新增 objective_reading_summary 模型角色，只根据实际读过的文本生成内容摘要和限制。没有读取的材料不生成阅读摘要。
- 摘要及内容摘要哈希持久化在研究断点的 reading_summaries。相同阅读内容复用摘要，新增阅读内容时重新生成该材料摘要。
- 每轮研究 payload 都包含 reading_memory，即使原来的阅读操作已离开最近三次工具结果。
- skill 明确 findings 为空不代表未读；摘要是导航笔记，不能替代原文证据。
- 摘要是额外模型调用，不占研究工具动作步数；首次恢复旧断点需要为已有阅读内容补建摘要。

## 真实验证

当前实验：data/experiments/egfr-research-budget24-20261113-173612/reading-memory-step-175020。

为 1 份 NCBI Gene 记录和 3 篇 PubMed 摘要生成阅读笔记，随后调用研究 agent。实际 prompt 中包含四份笔记。模型选择 finish_research，不再重复读取，返回 5 条 findings 和四份已读材料的 p0 引用；这次不是预算耗尽。

第一次接入探针发现新角色未加入请求 Literal 白名单，已修复 contracts.py；失败轨迹保留在 reading-memory-step-174902。

局限：此次只验证阅读记忆进入上下文及单轮行为改善，没有验证最终题目。模型返回的耐药统计把“已发生获得性耐药的患者”扩大成“接受一、二代 TKI 的患者”，仍需对照原文审查。实际摘要输出为英文，虽模板要求中文；不影响当前模型使用，但语言要求未完全遵循。尚未读取论文正文。

代码复核无高、中严重性问题。按单步调试要求，停止在研究子任务返回，未继续主 agent 出题。
