# 重复检索同一基因时的材料写入冲突

## 遇到的问题
任务 `web-c3e524c4-93c1-4df4-8d25-28a0acee3644` 在保存 Ensembl 材料时进入恢复状态。运行目录里有两份源记录为 `ENSG00000204438` 的 JSON，分别为 33,557 和 37,858 字节。比对后，只有顶层的 `xrefs` 字段不同。旧的材料 ID 和引文 ID 只包含来源记录和字段名，两份不同的原文会写到同一位置。

## 方案和实际改动
保留已有记录的写入冲突检查。结构化数据源在生成材料 ID 和引文 ID 时加入原文 SHA-256 的前 20 位，存储层仍校验完整哈希。相同原文可以重放，变化的原文能单独保存，各自的引文偏移仍然指向对应的文本。两个版本保留相同的来源记录 ID 和文档 ID，能够识别为同一来源。

改动位于 Ensembl、HGNC 和 NCBI Gene 共用的材料构造方法。旧任务的材料和引文仍可按原 ID 读取。旧任务首次重新检索时会使用新格式。

## 验证
结构化数据源、持久化和工作流调度相关测试共 37 项通过。新增用例模拟同一基因的交叉引用从空变为有值，检查两个版本的引文在写入后可按偏移读回，并验证再次读取相同内容会复用已有版本。原任务保留在断点，未用线上模型续跑。
