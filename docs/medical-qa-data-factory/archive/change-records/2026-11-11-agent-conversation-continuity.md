# Agent 的多轮阅读与上下文连续性：讨论及改造建议

日期：2026-11-11  
状态：已实施基础会话连续性改造；完整出题质量仍待后续验证。

## 1. 要解决什么问题

我们的目标是让 agent 围绕实体检索材料、阅读证据、形成自然且有依据的问题，为 query-planner 数据集服务。

目前单步调试出现反复阅读同一批材料的现象。问题不应简单归结为模型能力不足，也不能靠禁止重读解决。需要先检查：模型读到的内容，是否在后续判断时仍然可见。

核心原则：**先提供索引，让模型按需读取；读取结果进入连续会话，让模型基于结果继续行动。**

## 2. “一步”有三种含义

| 粒度 | 含义 | 示例 |
|---|---|---|
| 模型调用 | 一次请求与响应 | 模型决定读取 M0012、M0014 |
| 工具动作 | 程序执行模型选择的操作 | 读取材料并返回原文 |
| 业务步骤 | 完成一个阶段性目的，可包含多轮调用 | 判断现有证据是否足够形成一道题 |

一次业务步骤可以包含多次模型调用和工具动作。调试时可以在每次动作后暂停，但暂停不应造成上下文丢失。恢复时应延续暂停前的会话。

业务步骤只是便于观察的划分，不意味着重新引入固定流程，强迫模型依次完成预设动作。

## 3. Codex 和 Claude Code 的公开机制

以下依据官方文档，不能据此推断所有产品版本的内部实现细节。

### 3.1 模型选择工具，程序执行，结果回到模型

Claude 官方工具文档明确：模型输出工具名称和参数，应用执行工具，再将结果作为 tool_result 放入下一次请求。模型可以继续调用工具。

Claude Code 将整个过程描述为收集上下文、行动、验证、继续循环；具体动作由模型根据此前结果选择。

来源：

- [Claude 工具调用机制](https://platform.claude.com/docs/en/agents-and-tools/tool-use/how-tool-use-works)
- [Claude Code 工作原理](https://code.claude.com/docs/en/how-claude-code-works)

### 3.2 读到的内容是会话的一部分

Codex 官方指南的示例将 read_file 调用与对应 function_call_output 一起放入模型输入，输出中包含实际文件内容。Claude Code 文档也说明上下文包含文件内容、命令输出和会话历史。

这意味着“材料已经读过”与“模型现在知道材料内容”是两件事。目录和已读标记不能替代正文。

来源：[Codex 官方指南](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide)

### 3.3 压缩后继续工作，必要时重新读取

Claude Code 在接近上下文限制时自动压缩会话，保留请求和关键内容，但细节可能丢失。Codex 官方方案支持将压缩后的会话状态用于后续请求。

不能假定压缩保留所有证据，也不能把 OpenAI 的专用压缩结果直接用于 Qwen。我们需要借鉴会话连续性和按预算压缩的原则，而非直接复制专用接口。

来源：

- [Claude Code 上下文管理](https://code.claude.com/docs/en/how-claude-code-works#when-context-fills-up)
- [Codex Compaction](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide#compaction)

## 4. 我们已经观察到了什么

此前第 7–11 步审计发现：模型输入远低于总 token 预算，但观察层另设字符限制，将工具结果截成不完整文本。该问题已经修复，详见[此前改动记录](2026-11-11-observation-context.md)。

该修复保留最新一步完整结果，但旧结果仍受最近几步的观察范围限制。因此，材料曾被读取，并不意味着其原文仍在下一轮请求中。

随后针对第 13 步固定输入，进行了 12 次真实 Qwen 调用。只观察模型选择，没有执行工具或推进任务。

| 输入方式 | 输入 tokens | 包含重复阅读 | 只读未读材料 | 新检索 |
|---|---:|---:|---:|---:|
| 原输入 | 17983 | 3/3 | 0/3 | 0/3 |
| 删除旧笔记 | 17484 | 3/3 | 0/3 | 0/3 |
| 精简历史 | 13845 | 2/3 | 1/3 | 0/3 |
| 原输入补回 10 篇已读摘要 | 20944 | 1/3 | 1/3 | 1/3 |

补回摘要后，一次选择了更有针对性的 EGFR 检索，一次只读唯一未读材料，另一次仍包含重复阅读。

这些结果说明：删笔记或单纯缩短输入没有稳定解决问题；补回实际内容值得继续验证。但每组只有 3 次，不能证明唯一原因，也不能排除模型或 skill 的影响。

实验记录：[第 13 步对照报告](../../../data/experiments/prompt-ablation-step013-1794383145/report.md)。完整请求和响应位于同一目录；实验文件可能不纳入 Git。

## 5. 建议的目标流程

```text
任务：围绕 EGFR 形成有证据支持的问题

模型看到材料目录
  → 选择阅读 A、B
  → 程序返回 A、B 原文，加入会话
  → 模型根据内容发现缺口，搜索 C
  → 搜索结果加入会话
  → 模型选择阅读 C 的相关正文
  → 程序返回正文，加入会话
  → 模型结合证据形成问题
  → 检查问题和答案；需要时继续阅读、补证或修改
```

以上只是可能路径，不是硬编码顺序。模型可以决定读什么、读多少、是否继续搜索，以及何时形成问题。

材料索引建议包含稳定编号、标题、来源、内容简介、可读章节和阅读状态。原文存储在上下文之外，通过工具按材料或章节读取。读取后，实际内容必须进入后续判断所使用的会话。

## 6. 改造顺序

### 第一项：审计实际发送的会话

先核对代码和真实请求，回答以下问题：

- 每次模型决策是否重建一个新的状态 prompt？此前工具调用和结果如何进入它？
- 哪些结果只是落盘，哪些实际发送给了模型？
- 原文在哪一轮退出输入？原因是预算、步数窗口、字符截断，还是其他筛选？
- 单步暂停后恢复，是否还原了此前有效会话？

不能仅凭模型说“没有看到”判断输入缺失，应检查最终请求内容。

### 第二项：优先修复会话连续性

在现有循环上保留有效的模型动作及工具结果，并持续传入后续调用。不要仅因为超过最近三步，就把仍有用的证据从输入中删除。

材料读取结果应标明来源、材料编号、章节或段落范围，以及是否完整。工具失败和成功应如实记录；失败不能冒充成功结果，也不应覆盖已经取得的有效材料。

如果现有模型接口支持原生工具调用，可按其协议保存调用与返回配对；如果继续使用结构化动作 JSON，也必须保留等价的连续动作和观察记录。不能只更换消息格式而忽略内容是否保留。

### 第三项：达到预算压力时再压缩

每次发送前检查完整请求预算，包含 system、工具定义、会话内容和输出预留。

压缩时保留任务、已获得的关键结论、证据索引、适用条件、未解决缺口和当前进度。原始材料及完整调用记录继续落盘。压缩后的摘要是工作记忆，最终答案仍应能追溯到原文。

超大单次工具输出应支持按章节、范围或分页读取，避免刚压缩完就再次被同一份超大正文填满。

暂不把独立的“原文工作集模块”作为必需前提；先检查正常会话保留及预算管理是否已经足够。

## 7. 如何验证

1. 离线检查：连续读取 A、B 后，下一次判断输入包含对应内容；单步恢复不丢失它们。
2. 预算检查：低于预算时，不因固定步数窗口提前丢弃有效证据；需要压缩时，记录压缩前后内容及依据。
3. 固定输入对照：继续使用同一任务和材料，多次比较改造前后的动作选择，不通过 prompt 指定必须搜索或禁止重读。
4. 完整任务验证：观察能否从阅读推进到证据整合、出题和验证，而不只看重复阅读次数。

重读本身不一定是错误：确认细节、读取新章节、恢复压缩掉的原文，都可能合理。需要关注的是缺乏新目的、反复读取相同内容且没有推进任务。

每轮保存 system prompt、实际消息、工具定义、模型原始响应、工具参数及结果、上下文变更和 token 用量。日志分别标识任务、业务阶段、模型调用和工具动作，避免都被称为“一步”。

## 8. 本次结论

先让“读取 → 返回内容 → 基于内容继续判断”这个基本循环保持连续，再优化摘要、材料筛选和 skill。

## 9. 实施记录

本次保留现有结构化动作接口，没有迁移为原生 tool calling，也没有改变动作选择规则。

- `ObservationView.recent` 默认恢复全部历史工具结果，不再限制最近三步或独立的 16000 字符预算。相同 artifact ID 只保留一份，附带动作和步骤关联。原有显式字符上限仅保留给诊断调用。
- `ReactMainAgent` 明确说明观察列表包含连续历史；通过已有步骤记录关联调用参数与工具结果。
- `prepare_exploration_history` 将旧工具观察纳入实际请求预算触发的 LLM 摘要，最新一步结果不参与压缩。摘要保留来源、条件、缺口及失败信息，不能代替原始证据。
- 压缩后重新计算 `visible_source_text_ids`，记录 `compacted_observation_ids`。摘要以独立 conversation-v3 版本持久化，恢复时复用，避免混用旧研究便签。

验证：48 个相关测试通过，覆盖跨三步原文保留、预算触发的旧结果压缩、最新结果保护、恢复复用、可见编号更新、动作契约和执行状态。代码审查未发现阻塞问题。

真实验证使用第 13 步 before 快照，调用 Qwen 三次，不执行选择出的工具，不写入原运行状态。每次输入恢复 12 条观察、19 份已读材料的原文可见性。结果为：

| 调用 | 模型选择 | 说明 |
|---|---|---|
| 1 | 读取 M0009 | 只读唯一未读材料 |
| 2 | design_questions | 选择 M0018 的 ErbB4 研究形成题目，尚未执行出题，不能视为合格产出 |
| 3 | 读取 M0009、M0011、M0012、M0014、M0015 | 仍含重复阅读 |

完整请求（含 system prompt）、原始响应、决策和计数事件保存在 `data/experiments/conversation-continuity/`。探测脚本也保存在该目录。实验验证了历史内容进入模型输入，但三次调用不足以证明稳定质量改善；ErbB4 出题方向与实体目标的关系仍需评估。

边界：最新单次工具返回如果自身超过总预算，本次仍不能保证处理成功，应通过工具分页或限定读取范围处理。不同 artifact ID 中重复返回的相同原文目前不会按文本进一步去重。
