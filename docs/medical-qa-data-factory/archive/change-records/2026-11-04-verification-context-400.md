# 答案验证遇到服务端上下文超限

## 问题
任务 `web-2c6974bc-3575-4ff7-b77a-2e8d36cb5fab` 在验证 ZRSR2 的细胞遗传学位置时暂停。服务端四次尝试后报告输入至少 28,673 tokens，另请求输出 4,096 tokens，超过 32,768 的窗口。“至少”是下界，不能据此认定只差一个 token。

Ensembl 基因记录长 75,924 字符，不同转录本包含许多完全相同的外显子对象。原有压缩会合并字段名，但重复值仍占用输入。验证阶段走独立证据通道，外层探索的历史便签不会压缩这批证据。

## 方案和改动
在结构化证据压缩时，将内容完全一致的长对象存入行表，在每次出现的位置写入索引。保留数组顺序、出现次数和全部字段值。原始引文和持久化材料继续用于溯源。

若服务端仍报告上下文超限，适配器在既有重试次数内优先压缩可压缩的输入，同时将本次调用的输出预留减半，默认从 4,096 到 2,048、再到 1,024。上下文错误保留原结构化输出格式。若两项都无法再缩小，则返回错误。其他请求继续使用原配置。

## 验证
只读回放该任务的 Ensembl 证据，盲答阶段的证据部分从 89,365 缩至 26,868 个 JSON 字符。逐项解码后与原记录相等。反例复核使用同一份证据也通过了还原检查。模型适配器、上下文压缩和调度相关测试共 71 项通过。线上模型尚未续跑。
