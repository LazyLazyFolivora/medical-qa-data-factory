# Medical QA 前端改造计划：干净的研究工作台

## 目标

让研究人员快速完成「选择实体 → 运行生成 → 阅读题目 → 追溯证据 → 判断发布状态」。页面应清晰、可信、便于反复使用。旧交互样稿已在界面落地后移除；实现截图见 [研究工作台](../design/ui-directions/implemented-research-workbench-evidence.png)，截图使用测试数据。

## 设计原则

1. **题目和证据优先。** 生成结果及其发布结论是主内容；Agent 决策、产物计数、运行 ID 是可展开的辅助信息。
2. **使用安静的浅色层次。** 通过背景、留白、细分隔线和排版分组，避免高饱和装饰和层层嵌套的卡片。
3. **保证可读性。** 正文与表单标签不使用现有页面中大量 8–11px 的小字；长医学名称、ID 和中文标题可稳定换行；变化的数字使用等宽数字。
4. **状态准确。** 区分候选、验证、已发布、失败和 0 题。不能把示例产物或未审核答案标作正式结论。
5. **动效服务状态。** 用短促反馈说明任务启动、进度变化和证据展开；尊重减少动效设置。

## 实施顺序

### 1. 统一视觉基础

- 整合服务端页面的 `styles.css`、`workspace.css` 与 Vue 工作台的 `frontend/src/styles.css` 中重复的颜色、字号和组件规则。
- 定义颜色、排版、间距、焦点、按钮、表单、状态和空状态的通用样式。
- 保持现有 FastAPI 模板与 Vue 入口，先调整样式和信息结构。

### 2. 改造生成工作台

- 重排实体选择与生成参数，让主要操作在首屏清楚可见。
- 将任务状态、当前动作、通过题数和失败原因做成稳定的状态区。
- 让发布题目、答案和证据入口成为结果区主体；材料、Agent 轨迹和技术 ID 按需展开。
- 完整处理未开始、运行中、成功、0 题和失败状态。

### 3. 扩展到其余页面

- 统一任务、已发布题目、候选题目、审核和数据集页面的导航、筛选、列表、详情和状态表达。
- 在跨页跳转时保留实体、任务和问题的上下文。

### 4. 验收

- 在桌面和手机宽度检查布局、文字换行和操作入口。
- 用键盘走完实体选择、开始生成、切换任务、展开证据的流程。
- 检查加载、空结果、失败、长医学术语和大量运行记录。
- 保持现有生成与审核行为，通过前端测试和构建。

## 第一轮评审重点

先评审样稿的整体气质、信息层级和密度。确认后把设计映射到真实数据与现有组件，再扩展全站。
